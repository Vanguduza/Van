# 1. Purpose

This document is the **single implementation authority** for correcting VAN's current visuals and delivering a production-grade visual system across:

- floating assistant overlay;
- compact actions surface;
- expanded/working surface;
- docked edge presentation;
- Command Centre;
- state boards / acceptance boards;
- Android runtime implementation;
- Rive embodiment integration;
- Figma/source design authority;
- visual QA, regression and certification.

It is intentionally deeper than a descriptive design note. It is written so that an implementation agent, engineer, designer, or animation author can execute with minimal ambiguity.

This blueprint is designed to eliminate the current failure mode where the system delivers:

> character + circular background + tinted rounded rectangle + glowing stroke

instead of the intended result:

> **VAN as a living embodied assistant surrounded by a fluid refractive aura whose energy condenses into glass when interaction space is needed.**

# 5. Deep audit of the existing incorrect implementation

## 5.1 Core defects

The present visuals are incorrect in the following ways:

1. **Aura is implemented as a circular or elliptical background plate**, not a living field.
2. **Aura edge reads like a border**, not like optical energy.
3. **Glass reads as tinted dark acrylic** with a stroke rather than layered refractive material.
4. **State boards repeat one card silhouette too rigidly**, flattening state distinction.
5. **State glyphs look pasted-on**, not integrated into VAN's orb/visor/hologram system.
6. **Floating minimal mode incorrectly ships with a permanent card.**
7. **Docked mode reads like clipping**, not deliberate anchoring.
8. **Expanded overlay feels attached beside VAN**, not generated by VAN.
9. **Command Centre is underdeveloped**, generic, and too placeholder-like.
10. **Reduced-motion is not designed as a visual variant**; it looks like a disabled version.
11. **Effect-ladder degradation removes visual sophistication incorrectly**, collapsing toward circle + stroke.
12. **All 18 durable states are not fully represented in current evidence.**
13. **Character scale and crop drift across states**, weakening embodiment consistency.
14. **Status colours contaminate too much of the shell**, especially in degraded/warning contexts.
15. **Critical solid controls are present but visually detached from their decision context.**

## 5.2 Root cause

The implementation used a token-first approximation of glass/aura instead of a **composed multi-layer material system** with state-driven behaviour.

Specifically, the following model is insufficient:

```text
backgroundAlpha
+ blur
+ borderWidth
+ borderAlpha
+ glowAlpha
```

That model can generate translucency, but not premium glass, refractive presence, or embodied aura.

# 6. Corrected visual thesis

## 6.1 Core thesis

> **VAN is a solid expressive character surrounded by a living refractive field.  
When interface space is needed, that field condenses into glass.**

This means:

- aura and glass are one visual family at different densities;
- the character is the source of the interface, not content placed inside a card;
- state changes are embodied through pose, expression, visor, orb, aura, and then interface;
- colour supports meaning but is never the only semantic channel.

## 6.2 Visual grammar

The corrected system combines:

- premium dark DIAL base surfaces;
- fluid glassmorphic overlays;
- restrained refractive material behaviour;
- living cyan/blue electrical aura;
- selective amber/red/green semantic contamination;
- strong character-first hierarchy;
- controlled motion.

It does **not** combine:

- full neon cyberpunk overload;
- large diffuse blue blobs;
- equal-strength edge glow on every side;
- constant motion everywhere;
- hard circular halos;
- full-ring loaders behind the avatar.

# 8. Aura system — technical blueprint

## 8.1 Aura design goal

The aura must read as:

- **fluid**;
- **living**;
- **directional**;
- **state-reactive**;
- **glass-compatible**;
- **electrical but calm**;
- **premium, not noisy**.

It must not read as:
- a wallpaper circle;
- a soft backlight disk;
- a ring loader;
- smoke/fog;
- random particles;
- lightning.

## 8.2 Aura construction model

The aura is built from six mandatory layers.

### Layer A — core radiance
A compact low-opacity cyan/blue luminous body behind head/torso.

Purpose:
- establish presence;
- separate VAN from arbitrary host apps;
- provide base light source.

Properties:
- soft edges;
- asymmetrical offset allowed;
- no visible perimeter.

### Layer B — deformable outer field
A larger low-opacity field with controlled irregular deformation.

Purpose:
- prevent “static circle” reading;
- create life and spatial tension.

Properties:
- asymmetrical;
- non-closed;
- shaped by direction/state;
- domain-warped or equivalent authored deformation.

### Layer C — filaments
Thin directional energy threads.

Purpose:
- connect visor/orb/panel;
- communicate activity.

Rules:
- 2–5 active in full mode;
- tapered ends;
- not all parallel;
- not lightning;
- may feed into panel formation.

### Layer D — broken orbital arcs
Partial arcs only.

Purpose:
- structured technical energy language.

Rules:
- never a full ring;
- partial coverage only;
- uneven radii;
- low count;
- may phase/rotate slowly when allowed.

### Layer E — caustic/specular interactions
Bright localized optical interactions where energy meets glass or holograms.

Purpose:
- tie aura and glass into one material family.

### Layer F — bloom
A restrained post-light glow around only the brightest parts of A–E.

Purpose:
- perceptual light softness.

Rules:
- bloom is an effect result, not the aura itself.

## 8.3 Aura geometry starting tokens

```yaml
aura_v2:
  core:
    width_fraction_of_character: 0.88
    height_fraction_of_character: 0.78
    x_offset_fraction: 0.04
    y_offset_fraction: -0.03
    alpha_idle: 0.12
    alpha_active: 0.20
  outer_field:
    width_fraction_of_character: 1.34
    height_fraction_of_character: 1.18
    alpha_idle: 0.08
    alpha_active: 0.16
    asymmetry: 0.18
    deformation_strength: 0.07
  filaments:
    min_count: 2
    max_count: 5
    width_dp_min: 0.7
    width_dp_max: 2.2
    alpha_max: 0.42
  arcs:
    min_count: 1
    max_count: 4
    max_total_coverage_degrees: 220
    max_single_arc_degrees: 110
    full_ring_forbidden: true
  bloom:
    alpha_idle: 0.10
    alpha_active: 0.20
```

These are initial authority values, not arbitrary suggestions.

## 8.4 State-driven aura behaviour

Each durable state must modify **shape + energy behaviour + visor + orb + composition**.

### OFFLINE
- field collapsed;
- cool gray-blue remnant;
- orb asleep;
- visor dim;
- no active filaments.

### CONNECTING
- field forming in stages;
- one scan sweep;
- orb waking;
- partial arcs can grow in.

### IDLE
- calm asymmetrical breathing;
- 1–2 quiet arcs;
- low-motion presence.

### ATTENTIVE
- field leans toward target;
- slight forward emphasis;
- orb attentive.

### LISTENING
- field narrows upward;
- audio-responsive but smoothed;
- waveform-like modulation only in controlled regions.

### THINKING
- inward energy eddy;
- minimal motion;
- one subtle thought arc.

### SEARCHING
- one directional sweep through the field;
- lens/search cue emerges from orb or holographic layer;
- not a pasted magnifying glass.

### WORKING
- strongest operational field;
- active filament coupling to hologram/orb;
- more technical energy.

### DELEGATING
- branching outward routes;
- relay-node style activity.

### SPEAKING
- subtle energy synchronization with speech intent;
- never raw audio jitter.

### WAITING
- almost returns to idle;
- lower activity.

### WAITING_FOR_OWNER
- aura opens toward action card;
- amber attention accent localized to the request context.

### DEGRADED
- reduced energy complexity;
- fewer filaments;
- lower saturation;
- deliberate but still premium.

### WARNING
- caution caustic/edge contamination in one local region;
- no full-panel amber flood.

### ERROR
- controlled red semantic region;
- contained, not panicked.

### SUCCESS
- brief green-cyan release;
- quickly returns to neutral DIAL energy.

### URGENT
- narrow direct attention field;
- focused, firm, readable;
- no pulsing panic.

### SLEEPING
- breathing remnant only;
- orb asleep;
- visor off.

# 9. Glass system — technical blueprint

## 9.1 Goal

Glass must look like:
- premium;
- layered;
- optical;
- tactile but not heavy;
- context-aware;
- clearly distinct from a simple translucent panel.

## 9.2 Glass material stack

Every non-critical glass surface is built from:

1. **backdrop context layer**
2. **optional native blur / diffusion**
3. **dark absorptive tint**
4. **internal shaping gradient**
5. **fine material grain**
6. **inner highlight**
7. **structural edge**
8. **specular edge / caustic edge**
9. **aura contamination light**
10. **depth shadow**
11. **content**

### Required minimum fallback set
Even without true backdrop blur, the implementation must include:

- dark absorptive tint;
- shaping gradient;
- fine grain;
- inner highlight;
- structural edge;
- selective specular edge;
- shadow.

Without these, the panel will regress into dark acrylic.

## 9.3 Edge rules

Do **not** render one uniformly bright rounded border.

Instead:

- structural edge = quiet, low-alpha outline;
- specular edge = directional highlight with variable intensity;
- one side can nearly disappear;
- bright streaks appear only in short segments;
- state colour can locally contaminate part of an edge;
- full perimeter equal brightness is forbidden.

## 9.4 Glass V2 tokens

```yaml
glass_v2:
  compact:
    tint_alpha: 0.38
    tint_alpha_busy_backdrop: 0.48
    structural_edge_alpha: 0.08
    specular_edge_alpha_max: 0.30
    inner_highlight_alpha: 0.14
    grain_alpha: 0.018
    shadow_alpha: 0.24
    shadow_blur_dp: 18
    corner_radius_dp: 22
    native_blur_radius_dp: 24
  expanded:
    tint_alpha: 0.46
    tint_alpha_busy_backdrop: 0.58
    structural_edge_alpha: 0.07
    specular_edge_alpha_max: 0.26
    inner_highlight_alpha: 0.12
    grain_alpha: 0.016
    shadow_alpha: 0.28
    shadow_blur_dp: 24
    native_blur_radius_dp: 28
  command_centre:
    tint_alpha: 0.72
    structural_edge_alpha: 0.07
    specular_edge_alpha_max: 0.16
    inner_highlight_alpha: 0.08
    grain_alpha: 0.012
    native_blur_radius_dp: 18
  critical_action:
    translucent: false
    opacity: 1.0
```

## 9.5 Three execution paths

### Path A — native refractive glass
Use when true background/window blur is available and verified.

### Path B — overlay-safe optical glass
Default for floating overlay where real backdrop sampling cannot be guaranteed.
This is the main production path.

### Path C — opaque fallback glass
Use when blur, performance, thermal, accessibility, or platform constraints require it.

All three paths must preserve the same structural visual identity.

# 10. Character-to-glass composition rules

## 10.1 Resting floating state

At rest the assistant is:

```text
VAN + aura + optional orb
```

Not:

```text
VAN + tiny permanent card
```

Rules:
- transparent host background;
- no default card;
- invisible hit target allowed;
- resting state should feel lightweight and alive.

## 10.2 Panel formation

When a panel opens:

1. aura stretches toward panel origin;
2. a partial caustic/light seam forms;
3. glass body resolves from that seam;
4. VAN overlaps the new surface;
5. content enters;
6. filaments connect character/orb/panel.

The panel must appear **formed** by VAN, not mounted beside VAN.

## 10.3 Broken glass edge rule

Expanded and compact panels must visibly accommodate VAN's silhouette:
- panel edge may break, notch, bend, or allow overlap;
- character is partly in front of the surface;
- aura continues across/behind the surface;
- this is a key visual-signature requirement.

- hit target: 104 dp;
- character visual: ~92 dp;
- no default label;
- no permanent card;
- transparent host background;

- hit target: 88 dp;
- character visual: ~76 dp;
- preserve face/visor recognizability;
- crop through lower/side body only if needed;
- intentional edge anchor/wedge required;
- aura becomes edge-shaped/crescent, not clipped circle;
- magnetic dock behaviour;
- clear re-expand affordance.

## 11.3 Compact actions

- canonical width: 280 dp;
- maximum width: 360 dp;
- VAN overlap: 12–24 dp;
- typical actions: Ask / Projects / Tasks / Decisions;

## 11.4 Expanded / working

- larger context region;
- real task and progress meaning;
- orb and visor become more active;
- working state must not rely on generic spinner loops;
- panel surface still derived from the same glass system.

## 11.5 Command Centre

- responsive full owner-control surface;
- more opaque than floating shell;
- same glass DNA;
- hierarchy led by VAN hero and operational truth;
- not a generic dashboard.

# 13. Reduced motion and effect budgets

## 13.1 Reduced-motion goals

Reduced motion must be a **designed stillness mode**, not an impoverished version of the full mode.

Disable:
- hover/bob;
- filament travel;
- arc rotation;
- animated refraction distortion;
- particles;
- unnecessary spatial motion.

Retain:
- asymmetrical static aura;
- fixed partial arcs;
- expression and pose;
- state glyph where needed;
- consistent material quality;
- crossfades where necessary.

## 13.2 Effect-budget ladder

### FULL
- deformable field;
- filaments;
- arcs;
- bloom;
- optional blur;
- orb motion;
- full working effects.

### REDUCED
- fewer filaments;
- lower bloom;
- slower field update;
- no decorative particles.

### LOW
- near-static field;
- one or zero filaments;
- no live refraction;
- one fixed caustic.

### STATIC
- fixed asymmetrical field;
- fixed specular edge;
- no hover;
- no particles;
- expression and essential indicators retained.

# 16. Rendering architecture

## 16.1 Ownership split

### Rive owns
- character rig;
- face/eyes/brows/mouth;
- visor HUD;
- orb;
- pose states;
- action overlays;
- near-body holograms;
- body-linked micro-motion.

### Android/Compose/graphics layer owns
- overlay positioning;
- docking/dragging;
- panel geometry;
- broad aura field;
- glass material;
- specular/caustic panel behaviour;
- feature-detection-based blur path switching;
- effect budget selection;
- accessibility / reduced motion;
- state board composition.

## 16.2 Shared state object

A single canonical state object drives both sides.

```kotlin
data class VanVisualState(
    val durableState: VanState,
    val action: VanAction?,
    val attentionX: Float,
    val attentionY: Float,
    val speechEnergy: Float,
    val urgency: Float,
    val overlayMode: VanOverlayMode,
    val effectBudget: VanEffectBudget,
    val reduceMotion: Boolean,
    val crossWindowBlurAvailable: Boolean
)
```

No independent interpretation logic is allowed in separate subsystems.

## 16.3 Android rendering path recommendations

### API 33+
Use `RuntimeShader` / AGSL or equivalent GPU-friendly approach for aura field and local optical shaping.

### API 31+
Use runtime background blur only when available; do not assume persistence.

### Fallback
Use Compose Canvas / gradient and mask composition with deterministic fallback visuals.

## 16.4 Hard runtime rules

- do not screen-capture the host app for fake refraction;
- do not allocate large temporary bitmaps every frame;
- cache stable masks/noise resources;
- freeze or lower effect rates when docked/idle;
- suspend unnecessary animation when not visible.

# 20. Deep acceptance gates

## Gate A — No-circle aura
Fail if a reviewer's first impression is “blue circle behind VAN.”

## Gate B — No-stroke glass
Fail if the surface still reads as a filled rounded rectangle with a glowing border.

Blur/squint test: viewer should see **VAN first**, not card chrome first.

## Gate D — Arbitrary-background resilience
Must remain readable over:
- bright white background;
- dark app;
- saturated/photo content;
- dense text;
- map-like detail.

## Gate E — Grayscale state readability
At least warning, error, success, urgent, and waiting-for-owner remain distinguishable without colour.

## Gate F — Dock intent
Docked mode must look intentional, not clipped.

## Gate G — Reduced-motion quality
Reduced-motion screenshots must still look finished and premium.

## Gate H — Full contract parity
All 18 states and 14 actions must exist in evidence and runtime contract.

## Gate I — Command Centre maturity
No placeholder content or generic empty dashboard presentation remains in acceptance evidence.

## Gate J — Critical-action integrity
Critical approvals use solid surfaces and remain spatially attached to their originating context.
