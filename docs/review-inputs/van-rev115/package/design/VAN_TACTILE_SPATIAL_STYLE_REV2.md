# VAN Tactile Spatial Material System — Rev 2 (Graphite / Porcelain)

**Status:** design-system proposal aligned to locked owner dark/light references; **not approved native golden**. This improves the supplied `VAN_VISUAL_STYLE_CONTRACT_v1.md` but does not rewrite either locked benchmark or silently overwrite signed identity assets.

## 1. Preservation hierarchy

1. Original locked dark and light VAN design images remain immutable owner visual authority. `design/VAN_LOCKED_DARK.png` and `design/VAN_LOCKED_LIGHT.png` are sealed by their file hashes in the machine tokens.
2. This document is a *source-to-native reconstruction*, not a competitor template, a prompt that gets reinterpreted per screen, nor a claim that original token values were recovered.
3. The supplied Graphite Command V1 provides quantitative dark-role samples. Its 115 tokens, 16 recipes and five specimen tests remain reference evidence. Rev2 extends these into **30 scoped component recipes** plus equal light roles, 234 surface bindings, state rules and real native acceptance.
4. Exact Android OS status/navigation, dimensions, layouts and font artefacts must come from a native, version-pinned Compose build. Never place phone mockup hardware or iPhone Dynamic Island inside the Android app.

## 2. Distinct material grammars, identical interaction authority

**Dark:** graphite top-to-deep canvas (`#2A3235` → `#181D21`), satin surface (`#363D40` → `#293035`), inset chart (`#10181E`); silver typography and extremely restrained blue/cyan interaction accents. Cards are opaque machined blocks with a single upper seam, contact and ambient shadow—**not translucent generic glass**. The Home orb owns the richest material shading, while ordinary cards remain precise and understated.

**Light:** warm porcelain/silver canvas (`#FAF9F5` → `#EEEFEA`), white-to-warm-ivory cards (`#FFFFFF` → `#F5F6F3`), light cool plot inset (`#FBFCFB`) and charcoal typography. The metallic orb is a silver/ceramic sculptural object with realistic ambient occlusion and one low-intensity blue rim. The light theme must feel physically manufactured—never like flat white Material cards.

Light roles above are **engineered choices to match the locked visual**, not pixel-inferred original source tokens. Native golden approval may adjust measured values in a revised lock.

Charts are an intentional exception: a **flat precision plot inside a dimensional shell**. Overlaid price lines, SL/TP/entry labels and chart tools must be crisp; do not blur financial information for material effects. Buy/sell are directional, not profitable/unprofitable outcomes. Performance green/red comes only from verified account/position state.

## 3. Token and component acceptance

`VAN_MATERIAL_TOKENS_REV2.json` and `COMPONENT_RECIPES_REV2.json` are the single machine-readable style definitions. The original `VAN_VISUAL_STYLE_CONTRACT_v1.md` is preserved as a historical supporting reference, not an alternative runtime theme.

- Ordinary cards: 20 dp radius, ~16 dp padding, two-layer shadow, subtle edge highlight. UI elements may **never** apply global opacity to readable labels to create a material impression.
- Compact gutters 16 dp; sections 24 dp; related items 12 dp; no fixed-height crop of balances, labels or owner notices.
- Tap targets at least 48×48 dp; primary controls at least 52 dp high; focus remains visible across gradients and clipping.
- Typography roles 32/28/20/16/14/12sp as specified; tabular number layout. Font is proposed Inter pending license-compliant asset pinning—**no fonts included**. Financial amounts and quantities are never ellipsized.
- Micro-motion: 100 ms feedback, 160 ms ordinary transitions, 240 ms sheets. Offscreen renderers pause; high-priority status remains available without moving effects. Reduce motion to equivalent static cues. Effects never impair chart/graph gestures, TalkBack or device thermal behaviour.
- No colour-only signals. Risk text/accessibility meaning derives from source data; orb rim hues serve attention hierarchy but never override factual text.

## 4. Orb: one remarkable object, no legend

The Home orb is the large steel/ceramic centrepiece, not Floating VAN's avatar. Its event state is determined by a pure, versioned reducer over signed/revisioned broker, risk, DIAL and attention events. Priority: critical protection/kill switch → owner action/risk → stale/degraded/unknown → working/analyzing/active trades → verified benign event → normal. Each state has accessibility prose, source age and stable event identity. Visual animation is merely a projection. No RGB colour-cycling gimmick, homepage legend, forced heartbeat or uncontrolled GPU loop.

Tap opens a **compact anchored/partial-height Quick Hub**, initially at most three meaningful groups plus four or five navigation shortcuts. It may preview position performance, tasks/blockers, one alert, but never becomes a full dashboard. Tap an item routes to its actual source-controlled page; it cannot approve a trade, remove an account or trigger a task effect. Critical alerts are not cleared by closing the sheet. Home stays visually spacious.

Floating VAN keeps dock/drag/gesture/voice/multi-mode capability separately, but reads the same authoritative state fabric. It does not replace the main orb or promote ordinary notification taps to owner authorisation.

## 5. Functional screen families — material layout differs by task

| Family | Physical presentation | Why it differs |
|---|---|---|
| Home / Quick Hub | Oversized sculpted orb, two to three quiet action rows, anchored compact sheet | Primary status object; Home must not become a dashboard |
| Trading overview | One measured equity/heat tile plus Markets, Watchlist, Potential trades, Chart, Intelligence destinations; account and positions through contextual routes | Fast cognitive entry and complete discoverability |
| Instrument chart | Precision plot; ticker/timeframe and compact tactile control rails; order review in sheet; detail via focus | Plot dominates; effect controls remain outside untrusted bridge |
| Positions / Orders / Risk | Structured dimensional cards with exact values, unit provenance, protection and terminal order states | Readable exposure and reversible actions |
| Accounts / Funds | Identity/eligibility card, quoted amount/fee/beneficiary sheet, provider reconciliation timeline | Clear financial trust boundary, not glossy wallet theatre |
| Intelligence / News | Source-graded digest, evidence reasons, historical comparisons and counterarguments; drills to full report | Full analysis without pushing paragraphs on initial fold |
| Work / Projects / Agents | Physical phase rail, focused live dependency graph, evidence/status pane, semantic accessible list | Relationships are operational data, not decorative arrows |
| Muse / Hermes / Browser / ARTEMIS | Native viewport-first workspaces, scoped actions and verifiable receipts | A live remote task is not a screenshot or static badge |
| Memory / Automation / Settings | Calm provenance rows, consent controls, reliable run outcome states | Avoid projecting trading chrome onto unrelated tasks |
| Research / Forecast / Chain | Immutable outcome and evidence panel, model calibration/coverage, source age, experiment and rejection history | Scientific truth, not model-progress theatrics |

All 234 row-level profiles are included in `ALL_234_SURFACE_MATERIAL_ACCEPTANCE_REV1_13.md` and bound in `ALL_SURFACE_CONTRACTS.json` with one or more existing frontend units. Screen identity is not a claim that a new global navigation destination is needed.
