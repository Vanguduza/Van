# Rev1.18 — whole-product architectural revision

The active blueprint is `VAN_NEXT_UNIFIED_REBUILD_BLUEPRINT_REV1_18_20261021.md`. Its first part is the normative whole-product contract; the entire prior master remains embedded and preserved. Scope stays 324 requirements, 1,610 acceptance identities, 234 contexts, 349 original actions and 131 stable units. This revision strengthens existing obligations instead of counting additional paperwork as new functionality.

## Architecture improvements

- Three workload paths isolate financial execution/protection, owner interaction and heavy research; native domain owners retain authority, existing services are reused, and a shared Android bridge consumes typed state.
- One command/outcome protocol makes accepted, applied, cancelled and unknown distinct, with exact scope/revision/argument binding and original-operation reconciliation.
- Complete feature/context/action and capability-boundary registries feed the mandatory native catalogue. Specification IDs never pretend to be deployed routes.
- Signed zero-configuration bootstrap, trust/configuration rotation, re-enrollment, revocation and upgrade recovery have explicit lifecycle contracts.
- Local speech/VAD, transcript finalization, conversation context, spoken replies, barge-in, audio/OS interruptions and text fallback have separate typed state and measured qualification targets.
- Work/agents/Muse/Hermes, Studio, ARTEMIS, browser/files and automation gain concrete concurrency, lease, cancellation, DST/misfire and partial-outcome rules.
- Memory/privacy use a store/processor graph, separate correction/withdrawal/erasure, verified deletion and restore-time revocation/tombstone application.
- Cross-channel attention, native accessibility, both themes and S24 behaviour stay consistent with actual source state and OS permissions.
- Provider entitlement, budgets, backup/restore, signed release compatibility, security and independent native qualification are explicit exits, not green status inferred from connectivity.
- The existing financial/learning/research programme retains all required models, markets and boundaries; promotion still requires actual cost/risk/uncertainty evidence.

## Closure semantics

All 16 WPC issues have a normative design response in `contracts/whole_product/ISSUE_DISPOSITION.json`. Application defects, native registrations, exact provider-specific schemas/handlers, real provider access, economic results and signed app/S24 tests still require implementation and evidence.
