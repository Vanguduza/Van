# VAN whole-product architecture and completion contract — Rev1.18

This is a normative refinement of the entire Rev1.17 product. It resolves the design/ownership gaps recorded in WPC-001–016; source repairs, provider availability, economic outcomes and device acceptance remain execution obligations. It adds no runtime authority. The complete inherited trading, forecast, research, visual and owner-action requirements remain mandatory.

## 1. Product outcome and architectural decisions

VAN is one owner-facing Android product for trading, conversation and work across DIAL. It must provide trustworthy information, effective scoped controls, natural spoken interaction, and measurable learning where evidence supports it. Every domain has positive, refusal, unknown and recovery outcomes. A disconnected integration remains an explicit incomplete obligation, never a completed feature disguised as unsupported.

Use a modular existing gateway/application boundary, domain-owned ledgers and existing native services. Logical catalogue units are not deployment units. Do not create a new microservice for each feature, a second trading position book, a second Jev service, a competing scheduler or a universal agent that owns every effect. Separate a process only when measured failure isolation, latency, scaling or credential boundaries justify it. Record the boundary and operational cost in the existing complexity ledger.

Three paths have different budgets and authority:

- **Critical execution:** risk, order submission/reconciliation, per-fill protection and account truth. Consume qualified bounded snapshots. No remote model, speech renderer, graph layout or research task lies on this path.
- **Interactive control:** typed owner requests, conversation, approvals, task controls and read models. Acknowledge durable receipt promptly, then stream native operation progress. Acceptance is not completion.
- **Research and batch:** model inference, extraction, simulations, calibration, evaluation, file analysis and indexes. Use reserved budgets, bounded queues and cancellation; publish provenance-bound results for later consumers.

Use a ports/adapters architecture with one typed app bridge. Android owns presentation, audio/OS interaction and a scoped disposable cache. Each native domain owns state, authorization and effects. DIAL's actual owners retain mission/workspace/device leases. Hermes coordinates supported missions but is not a mandatory transit for direct admitted device, ARTEMIS, memory or read operations. The qualified native route is selected from capabilities, never guessed from a host name. Preserve the intended van-trading-core execution placement and admitted DIAL control/device owners, subject to source/configuration qualification.

## 2. Canonical contract resolution and compatibility

The following are mandatory, mechanically joined specifications:

1. `CAPABILITY_BOUNDARIES.json`: all 82 logical service owners, existing operations and domain contract profiles.
2. `FEATURE_CONTEXT_BINDINGS.json`: all 93 named features and 234 contexts, including additional context extensions and their backend/frontend owners.
3. `ACTION_CONTRACTS.json`: all 349 inherited actions with stable action ID, classification, exact subject/verb, input profile, positive/refusal/recovery oracle and effect boundary.
4. `PROTOCOLS.json` plus `RECORDS.schema.json`: request/outcome, event, provisioning, voice and admission contracts. Specialized financial/model schemas continue to govern their own data.
5. `ACCEPTANCE_REFINEMENTS.json`: mandatory scenario/oracle and owner additions to existing acceptance identities. `verification/EFFECTIVE_TEST_CONTRACTS_REV118.json` is the generated execution view. `verification/TEST_CONTRACTS.json` preserves inherited source records; runners and the rendered plan MUST use the effective view. Additions cannot remove inherited assertions or owners.
6. `QUALIFICATION_REGISTER.json`: every required domain/provider binding and receipt starts unqualified. This is a gate input, not a registry of deployed URLs.

Stable specification IDs are not callable endpoint assertions. At BE-032 each runtime operation binds an actual protocol and handler/route, input/output/error schema versions, native owner, consumer, authorization policy, idempotency scope, outcome lookup and freshness. A local navigation/control does not need a fictional server route. Existing historical endpoint references are candidates to reconcile against source and live readback. No required action may remain a free-text operation or an unresolved schema reference at BG-001.

For each capability, register all declared verbs and supported modes. Required-versus-optional applies to the declared scope, not to the current adapter's convenience. An unavailable required verb blocks its qualification. Optional provider-specific features disclose NOT_SUPPORTED with reason and tested alternative where the owner contract permits it. Never silently replace a funded operation with a read-only view.

All schemas carry a compatibility version. Unknown fields do not acquire authority. A client sends supported contract versions; the server returns the negotiated version and minimum supported client. Incompatible mutation contracts refuse before dispatch; permitted read-only degraded mode reports incompatibility explicitly. Keep a versioned upcaster only for safe data conversion, never for granting new actions. Backward compatibility expires through a declared rollout policy and tested signed-app upgrade.

## 3. One command/outcome protocol, native owners

A typed command binds owner/device, domain/account/project, exact subject, advertised operation/schema version, expected state revision, canonical argument digest, durable command ID, consent/policy epoch, expiry and required native proof. References to large artifacts include hash, media type, size, origin and admitted destination. Raw documents/transcripts/tool output are untrusted data, not instructions granting effects.

Flow: resolve capability → validate typed draft → preview exact consequential change → obtain required owner proof → persist immutable command/outbox → native owner revalidates current authority and revision → dispatch once according to provider idempotency → reconcile through native outcome lookup → project verified outcome. Retry transports the same immutable ID; changed parameters require a new preview and new ID. Proof is bound to exact arguments and cannot be reused after account, target, amount, lease or revision changes.

States: DRAFT, AWAITING_CONFIRMATION, ACCEPTED, DISPATCHING, RUNNING, SUCCEEDED, REFUSED, FAILED, CANCEL_REQUESTED, CANCELLED, OUTCOME_UNKNOWN. ACCEPTED means durable intent only; SUCCEEDED requires independent domain postcondition evidence. Cancellation acknowledgement is not native cancellation. A late external fact can reopen analytical reconciliation; it does not authorize redispatch. Terminal failures before dispatch are distinguished from unknown external effects. Domain machines retain more precise states such as partial fills and settlement pending.

Errors use stable categories AUTH_REQUIRED, SCOPE_DENIED, CONSENT_REVOKED, REVISION_CONFLICT, EXPIRED, NOT_SUPPORTED, DEPENDENCY_UNAVAILABLE, RATE_LIMITED, INVALID_INPUT, DATA_STALE, INTEGRITY_FAILURE and OUTCOME_UNKNOWN, plus domain-specific codes. Include safe explanation, retry policy, original operation lookup and source revision. Unknown transport errors never map to success. A server error cannot tell the client to replay a consequential command without reconciliation.

Financial money, price and quantity use the inherited exact decimal/unit contracts. A speech transcript, rounded widget or model output never determines an unvalidated quantity. Read operations have explicit cache/source-age policies; navigation changes no remote domain state. Local user effects such as clipboard, file save and microphone use still require OS permission/explicit intent and accurate local outcomes.

## 4. Events, projections, concurrency and offline behaviour

Each domain publishes source/stream identity, epoch, sequence, event ID, subject, revision, occurred/received times and payload schema. Snapshot plus cursor forms a consistent starting point. Dedupe by source epoch/event ID; detect gaps and refresh a bounded snapshot; reject incompatible epochs. Never merge a stale projection into current truth because its network arrival is later.

Use optimistic revision checks for mutable preferences/tasks and the native lease/fence for execution resources. An account/project context switch cancels obsolete reads and cannot silently rebind an already previewed command. Keep separate freshness for positions, quotes, tasks, voice and provider permissions. Coalesce disposable render ticks only; never coalesce away order, approval or ledger transitions.

Offline reads display timestamp and scope. Never queue high-impact financial commands for blind later execution. Drafts may persist as drafts; recovery rechecks capability, authority, revision and expiry before new confirmation. Persist pending original operation references across process death and app upgrade. Unknown effects remain discoverable even if the original screen is gone. A server-side schedule uses its native scheduler and standing authority rather than Android background timing.

## 5. Zero-configuration installation and device lifecycle

Preserve `com.dial.van` and admitted signing identity. Installation receives a signed, versioned provisioning envelope through the existing supported installer/intake flow. It contains issuer/key ID, environment/audience/app identity, route set, validity interval, nonce and enrollment reference. Secrets are delivered through the native secure enrollment owner, never in logs, QR history or manually entered backend fields. The app verifies the pinned issuer and replay/expiry/audience before enrollment and binds the hardware-backed device key where supported by the qualified policy.

Bootstrap states: UNPROVISIONED → VALIDATING → ENROLLING → VERIFYING_SERVICES → READY; explicit EXPIRED, REPLAY_REJECTED, TRUST_REJECTED, OFFLINE and REVOKED branches. Readiness includes actual owner-scoped gateway response and individual required service capability health. A TLS socket is not readiness. Complete device/owner enrollment may require normal explicit consent/biometrics; no host, port, token or certificate form is required in VAN.

Rotation is a signed configuration update tied to issuer trust and a monotonic configuration epoch. Validate the new route/certificate chain before activation; allow overlap only within the declared validity policy. Preserve original command lookups during transition. Root trust changes require an authenticated trust-update path, not blind acceptance of the new endpoint. Clock uncertainty refuses expiring effects and offers supported repair; no expiry bypass.

Lost/replaced/reinstalled phone creates a new enrollment with old-device revocation where requested. Restoring a backup cannot restore a usable copied hardware key or revive revoked scopes. Re-enrollment reconciles account/project/history with current owner policy. Local speaker-profile erasure remains possible when the backend is unreachable, according to its separate native biometric contract. First-install, revoked-device, certificate/route rotation, offline restore and signing-key mismatch are mandatory positive/negative/recovery cases.

## 6. Conversation, speech and bidirectional interaction

Preserve the admitted local Sherpa/acoustic asset and EnergyVadGate behaviour, authenticated POST/SSE fallback and speaker-profile controls already present in the action inventory. Do not replace these with a mandatory cloud-only voice path. Provider speech adapters may supplement the qualified local path where consent, language, quality and availability permit. Speech recognition, language reasoning, command execution and speech synthesis are separate capabilities with separate readiness.

Turn states: IDLE → LISTENING → TRANSCRIBING → INTERPRETING → RESPONDING → SPEAKING → COMPLETE. A turn may enter NEEDS_CLARIFICATION, AWAITING_CONFIRMATION, INTERRUPTED, CANCELLED or ERROR. Every event binds session ID, turn ID, sequence, revision and consent epoch. Partial transcripts are display-only. A final transcript may propose a typed intent; correction of account/instrument/amount invalidates the old draft. Multi-turn references resolve against explicit scoped context, not an implicit aggregate account. Explain uncertain recognition and ask a narrow clarification before consequential use.

Task-command state remains separate from turn/audio state. Saying “request accepted” follows durable command acceptance; saying “completed” requires independent effect success. A spoken answer can finish while a task continues, with an explicit pending reference. Failed TTS leaves the text and task outcome available. Reconnecting audio cannot replay an effect. Spoken prices, quantities, sign, currency and dates follow locale-safe templates verified against exact typed values.

Barge-in stops current playback and invalidates pending audio chunks for that turn/generation. It does not cancel an already-dispatched domain task unless the owner makes a distinct typed cancel request. Cancelled recognition results and old TTS chunks are discarded by turn/generation. Explicit no-speech and maximum-duration outcomes end capture; no indefinite silent recording. Speech end-of-utterance is based on actual qualified VAD or explicit owner stop. Always offer visible stop/mute and text/touch alternatives.

Default supported activation is explicit owner invocation from the app/floating surface. Always-on wake word is not assumed; it requires its own documented OS mode, consent, budget and actual device proof before enabling. Handle Bluetooth/headsets, route changes, incoming calls, audio-focus loss, lock-screen policy, notification/overlay permission and foreground-service restrictions. Microphone permission is OS state, not backend consent. Speaker similarity is revocable evidence, not sufficient financial authorization.

Pin initial measurable qualification targets: local capture feedback p95 ≤150 ms; stop playback after accepted interrupt p95 ≤200 ms; display accepted-turn acknowledgement p95 ≤500 ms once gateway receives it; first meaningful text/audio for a bounded non-tool prompt p95 ≤3 s on the declared qualified network/provider profile. These are engineering targets to measure, not achieved results or universal provider promises. A delayed response gives a truthful pending state; never invent an answer to hit latency. Long-running tools stream acknowledged progress. Record recognition task success and critical amount/account/instrument error rates on an agreed owner-language/noise corpus; any unresolved critical entity must clarify rather than execute. Language/voice availability and corpus qualification are explicit release artifacts.

## 7. Android, floating presence, attention and rendering

Use a single native OS capability adapter for permission readback, foreground services, audio focus/routes, secure storage, biometrics, file picker, clipboard and notifications. Feature modules consume typed states; they do not reimplement permission state machines. Runtime OS policy and owner choice govern what can run while backgrounded, locked, dismissed or rebooted. Unsupported persistent modes disclose their limit and a working foreground alternative; do not bypass platform controls.

One attention identity spans Home, Quick Hub, Android notification, floating workboard and optional spoken notice. Store channel delivery separately from incident resolution. Snooze does not resolve risk; dismiss does not cancel native work. Matrix: critical financial incident always remains in-app until resolved; noncritical items obey quiet hours and selected channels; OS DND/denied permission is reported as blocked delivery, never falsely bypassed. Lock-screen and shared-screen privacy masks amounts and sensitive text according to owner policy. Speech notifications require explicit channel preference and suitable audio/privacy state.

Keep Home compact, preserve Floating VAN's independent lifecycle and recognizable form, and preserve all 234 context contracts. Design by task: flat precise chart in a dimensional shell, focused graph with list alternative, explicit financial confirmation, conversation and contextual evidence panels. Apply the 21 October readability amendment, both themes, ≥48dp controls, 200% font-scale testing, TalkBack and reduced motion. Use native back-stack and stable deep-link subject references; invalid/revoked targets produce useful refusals.

Critical states remain readable when effects degrade: reduce shader fidelity, pause offscreen loops and use static material treatment. Measure chart/graph interaction, process-death restore, rotation/split-screen, memory, thermal and battery on the exact S24 OS/APK. The frame, battery and storage ceilings are versioned device qualification budgets; they cannot remain qualitative at QA-004. The inherited <150ms cached navigation and <500ms cached trading-first-paint targets remain.

## 8. Work, agents, automation, remote devices and studio

Projects/tasks use native IDs, versioned graph snapshots and explicit stage evidence. Edit checks expected revision; conflict returns both revisions for review, not last-writer-wins completion. A task can be RUNNING while its worker is unavailable; heartbeat and task state are separate. Graph layout/drag never dispatches native effects. Accessible list and graph derive from the same snapshot.

Steer/pause/resume/cancel/checkpoint bind native task/job/attempt, lease generation and scope. Cancellation states preserve whether the worker accepted cancellation, stopped execution and reconciled partial effects. On timeout, query the original operation; a new session must not create a replacement mission. A handoff explicitly transfers permitted native ownership or remains pending; a UI animation cannot transfer it. Provider ALLOW/DENY binds the exact current approval, original arguments and expiry. Shared Jev judgments remain advisory and bounded.

Automation definitions are immutable admitted versions with typed inputs, native step adapters, success predicates and per-step receipts. Each schedule declares timezone, DST fold/gap policy, misfire policy and overlap policy. Default: skip missed noncritical runs with visible reason, one active run per schedule, and no catch-up of consequential effects without current standing authority. Reminder due-time presentation may change timezone without silently changing the stored instant. Retries reconcile unknown steps first. Compensation is an explicit authorized operation, never an invented inverse for a financial or irreversible action.

Browser/device sessions bind lease, tab/target identity, viewport generation and admitted plan. Reobserve before effects if target changed. Files bind bytes/hash/media/size/destination and exact chooser/session; Android SAF consent and native provider admission are separate. Interrupted transfer resumes only with verified content identity and an idempotent provider protocol. Inert viewing does not imply import; provider claim does not imply persisted bytes; a GUI click does not imply task-goal completion. Treat HTML, attachments and clipboard content as untrusted.

ARTEMIS preserves device ID, OS/build, APK hash/signature, plan version, attempt and captures. A disconnect or missing capture cannot certify a pass; cancellation and recovery query the existing attempt. Studio/design/CI/security adapters expose exact source/workspace/artifact identity. CI success is not integration, deployment or owner acceptance. All tools retain their actual native owners and scopes.

## 9. Memory, knowledge, privacy and security

Use the native memory/knowledge store as authority; indexes/embeddings/summaries are derived projections. Facts retain source, owner/project scope, confidence meaning, revisions and contradiction. Correction supersedes a prior assertion; withdrawal removes it from active use while preserving applicable history; erasure is a separate scope-bound workflow. Goals and adaptation rollback affect only the admitted reversible fields and need current revision checks.

Maintain a store/processor graph for raw facts, transcripts/audio, local speaker profile, indexes, embeddings, summaries, artifacts, provider caches, diagnostics and backups. Each node declares owner, purpose, retention, encryption, deletion method, restore policy and lawful/required retention exceptions. Erasure states REQUESTED, ENUMERATING, DELETING, VERIFYING, COMPLETE, PARTIAL_EXCEPTION, FAILED. COMPLETE requires all in-scope stores' verified absence or declared excluded retention scopes; do not equate provider request accepted with erased. Tombstones/revocation epochs are reapplied before restored data becomes queryable. Deletion is not model unlearning.

Threat matrix covers every ingress/egress: forged intent, changed confirmation arguments, cross-owner/account/project data, malicious shared content or model prompt injection, chart bridge escape, replayed callback, leaked logs/screenshots, expired grants and restored revocations. Authoritative owners enforce refusal; the renderer is not a security boundary. Keep raw credentials out of prompts and diagnostics. Owner-safe export uses screened fields and exact record readback. Local file/mic/clipboard effects need explicit owner action and OS consent even when they never reach the backend.

Separate outcome explanation from causal proof; preserve complete opportunities, failed experiments, missingness and corrections. Jev/model qualification binds task, information cutoff, calibration target, resolved model epoch, cost and actual consumer. Durable global reservations cover failures/retries/unknown bills. Research outage cannot block protection, reconciliation or supported owner exits. Full trading and research features remain implemented even when an experiment finds no economic value; only their qualified use changes.

Portfolio, funding, account management and news retain exact native truth. All unsupported research/execution modes remain explicit. Read-only chain/prediction research gains no wallet signer, derivatives or live execution authority by integration.

## 11. Operational budgets, qualification and release

Keep domain-specific health dimensions: transport, authorization, source freshness, queue pressure, data quality, economic performance and native qualification. A single green badge cannot certify all. Store source/config/dependency/provider/build identity with every receipt. Redact correlation data without losing operation traceability.

Initial durability objectives: no acknowledged consequential command loss within the supported failover model (RPO 0 for durably accepted intent/financial events); backup restore alone does not satisfy this. Use validated durable replication/journaling plus native reconciliation appropriate to the actual deployment. Target control-plane recovery within 15 minutes of a declared supported single-host failure; protection must remain with the qualified venue/native contingency or explicitly enter its incident policy during outage. This is an engineering qualification target, not a present availability claim. Disaster recovery has a separately declared topology-specific RPO/RTO signed off before release. Immutable ledgers must be restorable with verified checkpoints and current revocations.

Bound queues by work class; reserve concurrency/rate-limit headroom for outcome query, cancellation and protection. Shed/cancel research before critical work. Reject new optional work when disk/queue thresholds jeopardize durable state; never discard acknowledged financial records. BE-033 publishes measured limits, alerts, runbooks, on-call owner, backup retention and representative load/failure/restore receipts. Provider timeout is a visible status, not an excuse to reset operation identity.

Provider qualification binds actual account/entitlement, API/model version, permitted operation, deployment environment, quota/fee/data-use terms and positive/refusal/recovery receipts. Required unavailable integrations block the affected gate; other independent work can proceed. No blueprint grants new spending, broker permission or procurement. Select targets using existing authorized access and record any external dependency explicitly.

Release binds `com.dial.van`, signing lineage, provisioning version, backend contract epoch, database migrations and exact APK hash. Migration must preserve pending original intents and enforce current revocations before serving. Rollback is allowed only against a tested compatible state schema; otherwise use forward repair/read-only incident mode rather than restoring old financial truth. Old APK retirement follows full feature/action parity and owner/device acceptance. Native F15, BG-001 and final owner acceptance remain distinct actual gates.

## 12. Whole-product acceptance and issue disposition

Every action requires its precise postcondition, refusal trigger, concurrency/unknown recovery oracle and readback owner. `ACTION_CONTRACTS.json` refines all 349 inherited title-only tests; compound legacy actions preserve all named sub-actions and must be expanded into individually exercised advertised variants at implementation. Selecting one happy branch does not complete a compound row. `DOMAIN_SCENARIOS.json` adds positive/adverse/recovery scenarios for all 24 audit families under existing test identities, and all 234 contexts inherit their applicable domain and cross-cutting cases.

The 22 mismatched feature primaries become mandatory additional acceptance owners in the effective test registry and generated plan; original owners remain. Voice's shared floating context also binds FE-021 as an accountable contributor through the context extension. No change to the 131 unit identities/dependencies or sole BG-001 is needed. This revision refines the existing 324 requirements and 1,610 acceptance identities; it does not inflate their number by counting templates as executed tests.

For each WPC finding, `ISSUE_DISPOSITION.json` gives normative artifact references, unit ownership, the mechanical/documentary check and the separate implementation/live exit. Design addressed does not mean source repaired, provider admitted, economy improved or handset accepted. Source/effect evidence starts NOT_RUN or NOT_QUALIFIED. Before BG-001 every advertised runtime contract has a genuine registered owner, client, qualified dependency and exact-source positive/refusal/recovery proof. Before release every native context/action, speech path and OS mode has applicable exact-build evidence. Profitability claims require the independent economic programme and prospective evidence, not product completion alone.
