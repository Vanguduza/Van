# Account-bound financial recovery

Three counterexamples through the actual DecisionCycle constructor reproduced cross-account contamination: a foreign win erased this account's loss counter, foreign losses triggered its cooldown, and a foreign owner resume replaced its high-water mark. The live account constructor and baseline restoration used the same unscoped folds.

Both runtime paths now select risk history using explicit native account identity. New trade reviews include the account inside their artifact seal; owner-reset/resume events include the configured, verified runtime account. Legacy reviews can join their exact original native RiskDecision/OrderCommand correlation. Reused trade IDs, contradictory labels, missing bindings, invalid native producers or seals and malformed/nonfinite financial outcomes stay unresolved. No configured name, singleton-account guess, path label or newly invented event assigns old facts to an account.

An unresolved record latches reconciliation failure and a separate persistent governor refusal. A reset or win cannot clear that refusal, and an adjustment snapshot without a strategy ID retains it. Constructors can still finish and existing protection continues. The actual service-start test verifies the refusal in its heartbeat and owner account readback; a separate existing-position test executes the venue stop while new entries remain blocked. Native source reconciliation, not a guessed policy reset, is required to resolve ambiguous history.

The single-symbol cycle also restores the account's recorded day/week baselines before its first snapshot/startup, retaining the existing period rule instead of treating a process restart as fresh daily capital. The multi-instrument runtime restores only its own baselines. Historical events and the original blueprint package remain unchanged. The old restart fixture now uses the actual native account-bound producer; separate negative tests preserve the requirement to refuse the previously ambiguous fixture shape.
