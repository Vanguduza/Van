# BE-004/009 candidate: current registry authority at each production entry

Ten new counterexamples showed that the production factory's cached paper adapter could still fill an order after account disable, local unlink, mode/environment/currency change, or a command targeting another alias/venue. The preceding native Deriv packet fenced its production path, but the other factory branches retained the stale-record behavior. This packet extends the existing entry boundary to those branches; it does not claim native identity qualification for every broker or exposure-safe unlink.

Factory-created paper, MT5 bridge, MT5 EA, cTrader and owner-ticket adapters now check the current registry under the shared account-operation and registry locks before delegating a new order. The lock spans the native submission. Alias/venue mismatches, missing or unreadable records, changed native/credential binding, a replacement mandate reference, disable and authority reduction refuse. Labels/notes do not change the entry boundary. Deriv keeps its existing transport-level fence, avoiding nested acquisition of the same file locks.

Only the entry method is bound. Adapter class identity and actual native methods remain intact, so paper finality/replay keeps its exact type checks and risk-reducing closes and stop maintenance remain available. Provider exceptions after delegation propagate as originally raised; they cannot become a fabricated pre-send refusal. Production services obtain these bindings through the real factory. Direct low-level research/test adapter construction is not a provider admission path.

Fifteen new cases include real file writers and a staged concurrent mutation, valid continued entry after a label edit, protective close after disable, and a provider failure after delegation. The current full trading suite passes 1,909 tests with zero skips using real private PostgreSQL and pinned DDS. The fixture is stopped and removed. Three induced faults are detected after a passing 15-case control and source is restored. All original 374 mutation identities and 383 edits remain; the current source preflight is separate from the previous source's hosted mutation execution.

This completes a prerequisite for safe local unlink, not unlink itself. Cross-host runtime revocation, active/pending exposure, unresolved order/close/funds effects, authoritative current provider readback, operation/result persistence and exactly bound owner resource versions still require their original source work. A per-host registry file is not a distributed lease. Remote closure, token renewal, funding and other product/provider qualification are retained. No new frontend, blueprint change, financial authority, native gate or handset acceptance is issued.
