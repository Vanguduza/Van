# LAC-348 original device reenrollment source candidate

This packet implements the existing BE-002 / VAN-NX-021 supported lost/replaced-device reenrollment workflow, specification operation WP-ACT-LAC-348. It does not add an owner action, alter frozen programme identities, qualify a device or issue deployment/release acceptance.

The existing dedicated DEVICE_ENROLMENT control submits one stable operation identity and exact original hardware-binding generation. One SQLite writer retires that original local binding, paired identity, grants, sessions, unconsumed same-owner bootstraps and undispatched privileged work, and records the original native-revocation operation and independent CA retirement outbox. Submitted/executing/verifying work remains available for original reconciliation. Competing intents must win the original binding CAS; an old retry cannot retire its replacement.

Replacement credentials remain inert until both the original strict native APPLIED result and CA retirement readback are proven. CA failure does not suppress the independent native-retirement attempt. The original protected response binds operator, operation, original binding, native operation, reason, gateway, credential hashes and original issue/expiry. Recovery returns those same bytes and deadlines; it does not mint another credential or extend expired authority. Retired device/key identities remain tombstoned and fresh reenrollment requires a fresh identity.

`GET /v1/devices/rebindings/{operation_id}` is the protected original receipt readback for the existing LAC-348 workflow. It requires the same dedicated control scope/operator, returns no-store responses, and does not start another retirement or native operation. Its source contract extends existing OF-PROVISION-001 and van.devices.provision; it creates no new public owner-action identity or frontend implementation.

Migration 60 adds the reenrollment owner and supports restart after DDL committed before its migration marker. All 59 previous migration SQL identities remain unchanged. Normal device revoke uses the same independent retirement barrier and reports certificate retirement as PENDING, APPLIED or UNKNOWN.

Worker evidence includes 229 affected cases before the final migration-idempotency repair, followed by 34 final workflow/migration/startup passes on the final source. The actual interrupted-DDL counterexample is retained. Independent frozen-source review verified the 13-path handoff, archive/patch and 59 prior SQL identities, then ran substantive SQLite/local-CA recovery/CAS probes with no blocking finding. These overlapping source checks are not a full-suite or native acceptance claim; final integrated guards and exact-head hosted CI remain required.

The existing installer consumer improvement remains a separately reviewed external patch because its repository path has no covering authorization yet. Eleven external source tests include its actual helper-to-gateway ASGI caller, but those tests do not make the uncommitted installer change available in this candidate or prove handset, native CA/provider or deployed behavior. BE-002 and all original source/native/device/security acceptance obligations remain open.
