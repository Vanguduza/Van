# Original native valuation lineage

Status: candidate source component. BE-006 remains IN_PROGRESS; unit, provider, risk-capital, settlement and production acceptance remain unissued.

`ValuationSnapshot` binds exact scoped Money values to an original account snapshot's native mark, source reference, native balance version, observation time and separately retained event/receipt clocks. It verifies the original producer, kind, schema, seal, native scope, account/currency/value agreement and strict boolean/integer types. Future or backdated availability, nonfinite or oversized amounts, a foreign scope and copied advisor payloads refuse. The native mark's balance-plus-net-unrealized basis excludes separate bonuses; optional manager/IB/nonwithdrawable credit values remain separate and missing values remain null. No historical credit is inferred from current credit.

Stored decimal scale preserves source value exactly. It is not a settlement precision or a conversion rate. Values stay in the original native deposit asset; the model does not claim complete position/holdings valuation, withdrawable cash, current collateral, settled profit or execution authority. A sealed caller-created model alone is insufficient proof of durable source observation.

`read_valuation` independently resolves the exact original row and scope from the existing SQLite/PostgreSQL financial ledger under a read snapshot. It checks original chain integrity, source-count/byte capacity and complete source readback. Missing references, partial reads and capacity exhaustion cannot become zero valuations. A caller-owned writer cannot claim committed source readback. The reader never appends facts or creates a parallel journal.

The existing period report now consumes these typed original valuations and exposes additive baseline/closing valuation detail. Original source references, marked-account interpretation, coverage, balance reconciliation and all existing hold/unknown states remain intact. External flows without historical normalized equity still yield NORMALIZED_HISTORICAL_FLOW_EQUITY_UNAVAILABLE, and new risk retains FLOW_ADJUSTED_RISK_NOT_QUALIFIED. The read model does not activate percentage performance for deposits or clear loss history.

An actual native-period counterexample also exposed a second rendering path: sampled drawdown from 3 to 2 differed under ambient ROUND_UP and ROUND_DOWN even after the unitization renderer had been repaired. The original failed report is retained. Period PnL and sampled drawdown now reuse that existing fixed 80-digit ROUND_HALF_EVEN renderer; exact fraction arithmetic and normal default outputs remain unchanged. Reporting tolerates unrelated inexact/rounded traps without inheriting their settings.

The final source selection executed 376 cases, including 45 new valuation cases, with actual isolated PostgreSQL, zero skips or storage-audit violations, matching final runtime/test hashes and independently confirmed fixture removal. Seven supplemental faults were caught by assertions; all source bytes were restored, with 20 positive and 20 restored SQLite controls. Supplemental PostgreSQL parameters were explicitly deselected only in that fault exercise and executed in the final actual-PostgreSQL selection. Counts overlap. Exact commands, hashes and outcomes belong to receipts/NATIVE_VALUATION_SOURCE_20261026.json and ci/native_valuation_20261026/.

This component does not complete multi-asset valuations, qualified historical flow adjustments, FlowAdjustedRisk, append-only reversals/compensating fill-fee facts, shared reservations or BE-007 native payment rails. Full backend/forecast/assistant work and independent/native/Android/Artemis-S24 qualification remain required. No frontend redesign precedes BG-001.
