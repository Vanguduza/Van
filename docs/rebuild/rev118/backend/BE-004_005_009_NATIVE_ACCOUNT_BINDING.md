# BE-004/005/009 candidate: native account identity and credential verification

The production Deriv factory now binds native authorization to the registered login, exact currency, actual `is_virtual` value and token scopes. A user label, login prefix or successful websocket connection is not verification. Missing/ambiguous fields and nonfinite balances refuse. This partial source milestone preserves the original account/provider/risk programme; it does not qualify an exchange, a product family, a live account or an entire unit.

Thirteen original native-frame counterexamples reproduced wrong-account/environment/currency/read-only verification and actual buy submission, plus a configured read-only account being widened by a trade-capable token. Seven further real-handler counterexamples reproduced unverified credential replacement, failure to bind an initially unbound account, unchecked OAuth identity and alias overwrite. The new tests use the real factory, websocket framing, Commander writers and private temporary files. They do not contact a financial provider.

The source contract was checked against the official Deriv v3 authorize receive schema at `binary-com/deriv-developers-portal` commit `406101967971450321434cb71d6de6e72742247f`, file `config/v3/authorize/receive.json`, SHA-256 `65910bac7ac9aa1f7e39533a3f4ba380c68523cdad314af36b691ff5a360f914`. It defines `loginid`, integer `is_virtual` 0/1, currency, numeric balance and scopes. The application requires its identity/permission fields even where the provider schema makes them optional. No permission is inferred from an omitted field.

Private calls authorize each new socket. A changed vault token is reauthorized on an existing socket before use. Public market-data calls remain unauthenticated. Requests and responses are serialized through one lock; reconnect never resends a buy/sell whose response was lost. Native money numbers parse directly to Decimal. A failed identity or unavailable portfolio is unknown exposure, never an empty successful portfolio. Adapter diagnostics retain placeholder tokens, and connection/library errors do not expose credential-bearing exception text.

Production entry checks run under the same per-account operation lock and registry lock used by account mutations. The lock spans the native send/response. Disabled/read-only/shadow accounts, changed native bindings and changed environment cannot overtake a checked buy. A command for another alias/venue refuses. Mode reduction does not remove the separately bound protective portfolio path. Both actual service constructors also refuse a signed sending mandate that exceeds the configured mode or crosses demo/live identity. Limited authority remains available under a more permissive configured ceiling.

The existing Commander verification path now retains production binding when a test connector is injected. Credential replacement validates candidate material before replacing the active private file; rejected login/environment/currency/scope/app-ID changes preserve the old file. An initially unbound account is pinned from verified native readback under the account-operation lock. OAuth linking checks native identity before creating local files and refuses an existing alias. Demo creation checks alias collision before requesting the remote account and verifies returned material before local registration. Native read-only OAuth access remains linkable as OBSERVE. A live OAuth account remains OBSERVE even when its token permits trading; no mandate is created.

This is not a distributed transaction across the registry and secret files. An interrupted first binding or link remains subject to the existing native verification and OAuth UNKNOWN recovery fence. Generic account actions still require durable operation/resource-version reconciliation; native account creation after a lost reply is not made safe by a file lock. Environment-variable mutation by an external actor is not serialized by the Commander lock. Windows locking, genuine token renewal, all other broker families, authoritative retained-funds readback and exposure-safe unlink remain work. In particular, local account removal is not yet qualified for active exposure and must not be described as remote closure.

The inherited Deriv product request/settlement model also remains incomplete: multiplier and other product-specific parameters must be sealed into the native command, attached protection and settlement need product-specific proof, and cash proceeds cannot stand in for filled instrument quantity. This identity packet does not relabel those families as implemented. Existing CALL/PUT direction mapping is retained. Real provider matching and recovery, supported CEX spot integration, funds/custody, account-wide unknowns, policy evolution and independent gates remain original obligations.

The packet passes 83 focused account/credential/constructor cases and 82 gateway cases, with zero audited checkout runtime-storage writes. The full trading run passes 1,874 tests without skips using real PostgreSQL and the pinned DDS source; 18 new constructor-mode tests and two further credential positive/preflight controls were added afterward and passed in the 83-case focused run. Six distinct induced defects are detected after a passing 67-case control and source restoration. An initial mutation-oracle run correctly refused to count a fixture AttributeError; the constructor boundary now has an explicit forbidden-entry assertion. The original 374 mutation identities and 383 edits are preserved. See the associated receipt for exact hashes and cleanup.
