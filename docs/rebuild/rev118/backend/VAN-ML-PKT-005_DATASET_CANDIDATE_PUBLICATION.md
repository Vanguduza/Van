# Durable DatasetManifest candidate publication

Status: source-tested component. ML005 remains IN_PROGRESS; no formal unit, dataset-use, provider or production acceptance is issued.

`DatasetCandidateArchive` publishes immutable candidates through the existing VATI SQLite/PostgreSQL ledger owner. It requires a dedicated source-only book and refuses mixed financial or other event kinds. The canonical DatasetManifest schema remains unchanged. Candidate metadata is not an admitted dataset or a data-use grant.

New publication independently inspects the original native archive and Parquet bytes before entering SQL. A stable request binds the requested manifest and exact native scope. The SQL writer rechecks that identity, serializes competing publishers, enforces global event/byte capacity and prevents record-ID reuse. Creation time comes from the actual writer clock; backward time refuses. Both the requested representation and writer-created representation remain durable. Local writer time is not independently qualified source time.

The service independently reads back the committed original before returning completion. Caller-owned transactions and read snapshots cannot claim durable publication or lookup. Lost ACKs and missing original readback return an explicit unknown state that must be reconciled using the original request. Exact replay returns the original receipt without source rereading, timestamp renewal or another append. Different requests cannot rebind the same record, and different content cannot reuse an original request.

Historical lookup and current source inspection are separate operations. Deleted or damaged source bytes do not erase an original receipt; they prevent current inspection and new publication. Recovery validates original envelopes, sealed canonical metadata, request fingerprints, source-witness shape, clocks, event count and the actual ledger chain. Even a correctly sealed but incompatible record refuses recovery. No unqualified current-use success is inferred from a historical receipt.

The existing slow research workflow and real CLI expose `dataset_candidate_publish`, `dataset_candidate_lookup` and `dataset_candidate_inspect`. Publication/current inspection require explicit existing native archive and source-partition paths; cold lookup requires only the original source ledger. Ledgers close on every CLI exit. Receipts state `CANDIDATE_PUBLISHED_NOT_ADMITTED`, false research/current-use qualification and authority `NONE`.
