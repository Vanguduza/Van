The archive groups observations by native provider, actual demo/live host, native account, native product and timeframe. Tickers cannot merge different products or accounts. Every record retains its original contract and observation, request identity, predecessor hash, revision and archive availability. Hash/path, sequence, strict typed scope, market values, native precision, optional-delta provenance, pagination, absent spread and unqualified calendar/authority states are revalidated on durable readback. Corrections and contract changes append revisions; original snapshots and as-of availability remain available. Empty observations preserve unknown pagination and explicit unqualified empty state.

An atomic, flushed immutable record-file rename is the durable commit point. The head is a derived index. An interrupted head update leaves the original record independently readable; replay repairs the index without a second revision. A conflicting/ahead head, missing committed tail, corrupt record, noncanonical bytes, wrong scope or symlink refuses reads. Recomputed file/observation hashes cannot waive semantic validation. Source integrity is not adversarial filesystem authority or an independently signed certificate. Deleting an entire archive and all of its anchors requires external backup/retention qualification; this component does not claim to detect every external rollback.

The existing cross-process state-file lock serializes append and captured reads; independent requests can proceed while a provider read is waiting. No financial journal lock or protective/order socket is held during collection. Explicit absolute storage is required. The archive has capacity refusals at10000records per scoped partition and8MiB per record; no implicit retention/deletion policy is introduced. This is an implementation resource limit, not production capacity qualification.

The additive read-only market reader uses an independent native connection. It authenticates, captures the native symbol list and only the selected product's details, verifies the expected contract revision before requesting history, and closes its reader. The actual protocol fixture observes exactly five requests for a successful first capture: application auth, account auth, symbol list, selected symbol detail and trendbars. A changed contract refuses before the history request. The collector validates the original window, serializes the same scoped request, reads back a completed original before reconnecting, closes failed readers and publishes no synthetic empty success. It exposes no order or withdrawal method. Different request IDs may create later source revisions; the same ID cannot rebind its original window/contract.
