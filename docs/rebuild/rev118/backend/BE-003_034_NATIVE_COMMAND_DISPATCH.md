# BE-003/034 candidate: responsive and bounded native Commander execution

A real HTTP/provider-frame counterexample showed that the async Commander route called a blocking broker handler on its event loop. A provider authorization wait prevented health and account status reads until verification returned. This prevented the operation polling needed by the remaining account-recovery work.

The existing process now runs reads and the separately authorized halt path outside the event loop. Other commands use one serialized native executor, preserving write ordering across different command types. The executor accepts at most 16 running/queued commands; overload refuses before dispatch. Cancellation or loss of an HTTP waiter keeps the admitted native work and its capacity owned by the executor until it completes. The connection ending is not an explicit native task-cancel operation. This prevents cancelled queued requests from reopening capacity while their work remains outstanding.

The route still authenticates and consumes the global one-use nonce at ingress. At actual dispatch it rechecks the original signed envelope against current keys, principal and the existing timestamp window, without consuming that nonce a second time. A request that expired in the queue cannot execute. Native lifespan shutdown stops work that has not started and waits for actual running work; an executor that has shut down refuses new writes. Read classification is an explicit list, so new commands default to serialized execution.

Five source cases cover actual broker-frame waiting and live HTTP reads, a cancelled running waiter and a following write, an admitted request whose authorization expires in the queue, cancelled queued waiters with overload, and a closed native lifecycle. The full trading suite passes 1,931 tests without skips using real private PostgreSQL and pinned DDS source. The combined native dispatcher/account suites pass 26 tests. Five induced faults are detected after a passing five-case control, and source is restored. No inherited mutation identity is removed. The private PostgreSQL fixture is stopped and removed.

The separate frozen backend/contracts audit at `4fb7be1e` passes 6,619 tests with 166 explicit skips and no failures, zero forbidden checkout storage events and a clean worktree. That evidence belongs to its exact source; it is not silently attributed to this later dispatcher change. The previous source's escaping failure is retained as failed evidence.

This change does not provide durable generic operation IDs/results, process-death reconciliation, explicit native task cancellation, provider matching, cross-host account leases, exposure/funds-safe unlink or whole-unit admission. A disconnected caller still needs the original operation's eventual native result, and may not repeat an effect merely because it lost a reply. Continue the original account-operation journal and recovery packet on this execution boundary. No new service, owner financial permission, UI/prototype, live-host deployment or handset acceptance is introduced.
