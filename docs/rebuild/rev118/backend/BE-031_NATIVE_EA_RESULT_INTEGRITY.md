# Native EA result and numeric integrity

The inherited EA rounded volumes to two decimals, prices to five and cash/profit to two. It treated an order ticket as a position ticket, reported partial closes as full fills, accepted the `CTrade` boolean as a confirmed stop change, and treated ambiguous post-submission errors as proven refusals. An unprotected fill also generated two contradictory results for the same immutable queue claim. The pull client invented stop confirmation on a close and converted a null position ticket into the literal `"None"`.

The candidate serializes finite native doubles with 17 significant digits and uses JSON null for invalid numbers. Position read failures make the entire observation unavailable instead of silently removing exposure. Symbols are escaped as JSON strings. Native entry permissions and finite positive quantity/stop, valid side and supported order type are checked immediately before submission.

Entry results retain the distinct order and deal IDs. The deal's `DEAL_POSITION_ID` is resolved to exactly one current matching `POSITION_IDENTIFIER` and symbol; the EA never guesses a position from its order ticket or symbol alone. An unresolved ticket remains null. Stop confirmation requires a current native stop at least as protective as the requested stop. A missing stop retains the original fill and separately records the emergency close against the resolved position; it never rewrites the fill as a no-effect rejection. Original volume/price/retcode are captured before that protective action can overwrite `CTrade`'s mutable result.

Partial closes remain PARTIAL. Explicit native refusal codes are distinguished from timeouts, connection failures and other uncertain effects. Stop modifications require a positive finite stop, forbid widening, and require both the native success result and confirming readback. A success acknowledgement without confirming readback is UNKNOWN. Missing native close protection remains unconfirmed in the Linux client, and null position IDs remain absent.

`trading/tests/test_mql_native_function_bodies.py` extracts the actual EA function bodies unchanged and compiles/runs them against `mql_terminal_fixture.cpp`, a controlled C++ terminal interface. This executes the branches under test rather than a rewritten EA simulator. It does not execute MetaTrader: the terminal APIs, financial effects and string-format compatibility are modeled, and complete EA compilation is independently checked by the Windows MetaEditor job. Original controls produced 18 failures and four passes; staged entry checks produced four further failures, and three Linux-consumer checks exposed the client gaps. The receipt records final focused/full/rebuild and restored-fault results when available.

Remaining native obligations include deferred worker deadline/lease/authority envelopes, append-only pending/late/corrected order and financial facts, complete pending-order snapshots, exact funding/finality and terminal/broker acceptance. A source compile, modeled function execution or regression suite issues no unit, provider, production, profitability or S24 acceptance. The original programme and frozen package remain unchanged.
