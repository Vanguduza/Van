# BE-002/005 candidate: exact OAuth state, broker and device scope

Three real gateway counterexamples are fixed: a Deriv callback with no state silently adopted the most recent flow; a Deriv callback could populate a cTrader flow; and a second authenticated paired device could inspect another device's pending broker accounts. All three pre-fix cases failed with actual HTTP 200 responses where refusal was required.

The existing authenticated account-action route now supplies its verified device identity separately from the signed provider arguments. OAuth start records that identity in the encrypted pending payload. Pending readback and linking require the same device, and the callback must name its exact opaque state and broker. Client-supplied owner fields cannot choose the binding. Neither a missing nonce, the current session's device nor the set of other states can adopt a legacy unowned row. The original device boundary survives a new pending-reader instance with the same persistent encryption key.

Unreadable ciphertext returns an explicit 409; expiry remains distinct from readiness and releases no account identifiers. Callback HTML now describes authorization receipt, leaving account linking to the app's existing owner-approved action. Success/error pages send `Cache-Control: no-store` and `Referrer-Policy: no-referrer`. No new Android configuration or UI flow was added: the existing account request already carries the authenticated device ID.

Measured source evidence is in `../receipts/OAUTH_STATE_SCOPE_SOURCE_20261022.json`: 39 gateway/account tests, 192 owner-registry/Artemis-plan source contracts and 78 rebuild checks pass. Seven new cases include real paired-device signatures, original-owner happy readback, wrong broker, absent state, expiry, a restart, unreadable state and refusal to adopt a legacy row. Three induced bypasses are detected after a passing control and the source is restored. Endpoint citation regeneration preserves all feature/screen/function IDs and their authority/history; it does not promote any prior qualification.

This is a partial milestone. Provider redirects in these tests contain isolated fixture tokens; no live OAuth provider was contacted. Durable callback/link claims, collision handling, unknown external effect reconciliation and process recovery are the next source work. A callback result still must not be replayed automatically after an uncertain token exchange or link. Native live/demo/read-only identity and exposure/funds/lease-safe unlink remain other required BE-004/005 work. Nothing here issues a unit, gate, provider, production, release or handset acceptance.
