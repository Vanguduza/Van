# Native MetaEditor source compilation

`van-mql-native-source` runs on a disposable Windows Actions runner when the EA, compiler script or workflow changes. It also supports manual workflow dispatch. It uses a read-only repository token and no owner, DIAL, broker, handset or deployment credentials.

The compiler script obtains the installer linked by the official MetaTrader download page, requires an admitted HTTPS MetaQuotes distribution location, pins the bootstrap hash observed in a native Windows run, and verifies the Windows Authenticode publisher before execution. It records installer and compiler hashes, signature identities and the actual compiler version. Installer preparation is bounded. Executable and MQL5 data/library discovery support both portable and standard installations; setup-window and file diagnostics are retained when preparation fails. If a signed SDK executable is installed but standard-library data has not been initialized, it opens the signed editor to seed its data. Any subsequent terminal initialization runs on the disposable VM with an enforcing outbound program block, all experts disabled and no account credentials. It stops before the EA is copied or compiled. No EA is attached or trading command issued.

Compilation uses the [documented MetaEditor command-line interface](https://www.metatrader5.com/en/metaeditor/help/beginning/integration_ide#compiler): `/compile`, `/include` and `/log`. Windows line-ending conversion is disabled before checkout, and the EA's raw blob identity must match its exact Git object. It is copied byte-for-byte to a fresh temporary directory. A deliberately invalid source file must produce native compiler errors and no executable; otherwise the compiler-result check fails. The actual EA must then produce a fresh nonempty EX5 and a native log reporting zero errors. Warnings remain visible in the receipt and log. An exit code by itself never establishes a successful compile.

Artifacts contain the native logs, the source-candidate EX5 when compilation succeeds, and a receipt with the exact checkout and source/tool hashes. They exclude the proprietary SDK/installer. Download, publisher, installer, timeout, unreadable-log and compilation failures fail the job and retain the observed failure. The current upstream installer supplies the SDK; its actual version is recorded rather than described as a pinned release toolchain.

Local PowerShell grammar and workflow YAML checks validate the runner before publication. They do not run MetaEditor or establish MQL correctness. The first hosted attempt verified the signed official installer but failed SDK discovery; no compiler case executed. Its input fingerprint was the deterministic CRLF checkout transformation, now prevented. `receipts/NATIVE_METAEDITOR_a1ee86b2.json` retains that actual failure. The next attempt proves exact Git source bytes and an installed compiler executable, but still cannot locate its library; `receipts/NATIVE_METAEDITOR_8d2f5388.json` retains that result. Bounded offline data initialization awaits its own native run. Actual hosted compilation remains pending until a subsequent native artifact proves it. Even a successful native source compile does not establish terminal order execution, precision, provider finality, live trading readiness, deployment, profitability or handset acceptance. Those remain the existing BE-031 and original release obligations.
