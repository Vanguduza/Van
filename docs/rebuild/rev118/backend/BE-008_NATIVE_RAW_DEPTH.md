# Original native depth changes

BE-008 remains IN_PROGRESS. This is a tested source component; no unit, provider or live-market acceptance is issued.

The existing cTrader transport already fenced depth events from retired connections. The adapter had no depth consumer, subscription control or read model. The new DepthBook consumes the pinned native `ProtoOADepthEvent` and `ProtoOADepthQuote` contracts. It preserves unsigned 64-bit quote IDs, prices and cent sizes without floats, applies quote replacements and known deletions, sorts original levels deterministically, and exposes bounded display truncation separately from source counts.

The pinned depth protocol contains no native timestamp, sequence or snapshot-complete marker. Its depth-price fields have no explicit scale definition. Raw depth therefore retains integer prices and an explicit unresolved scale; spot-price documentation is not promoted into a depth-price qualification. Snapshot completeness, current native freshness, executable liquidity and tradability remain unqualified. Empty observed changes do not prove an empty market. One-sided and crossed observed levels remain explicit.

Depth subscriptions are requested once per current connection/product/contract. Acknowledgement means queued control, never delivered data. Local unsubscribe removes eligibility before native I/O. Unknown or invalid control replies cannot be blindly retried on the same connection. Malformed changes, unseen deletions, ambiguous quote identities, clock regression and capacity exhaustion latch recovery until a fresh native context. Backlogs and expired processing age withhold displayed levels; no-op events cannot renew the age of original depth changes. Contract/account/environment changes never reuse a prior ladder.

`MarketReader.read_depth` uses the existing bounded independent read connection and verifies the requested native contract. Its read-only transport adds only depth subscribe/unsubscribe messages. Order submission, position closing and unrelated account reads remain refused. Depth selection leaves original financial execution events queued for their existing reconciliation owner. Reader closure joins its original socket worker; fixture peers and readers are closed and reaped by the actual suite.

Evidence: 31 new source cases; 171 focused depth/spot/transport/archive/feed passes; five supplemental assertion-caught faults with 31 positive and 31 restored controls and exact source restoration. Final combined selection: 738 passes on SQLite and an actual isolated PostgreSQL fixture, zero skips or storage-audit violations, all 492 runtime/test hashes matching, and the owned fixture independently absent. These counts overlap. Supplemental faults are separate from the canonical 374-case/383-edit corpus.

This component is an ephemeral native read model. Durable depth capture/revision/as-of recovery, qualified depth price semantics, service and existing-screen consumption, provider entitlement/health, continuity recovery and the remaining market/venue operations still need implementation and qualification. No HTTP endpoint is added or market monitor relabelled LIVE. Source presence does not enable a production subscription or frontend feature. Full backend/ML work and native admission, production-profile provisioning, signing/deployment, economic evaluation and Android/Artemis/S24 acceptance remain required. No frontend redesign precedes BG-001.
