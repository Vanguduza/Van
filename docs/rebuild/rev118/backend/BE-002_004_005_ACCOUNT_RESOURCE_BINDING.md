# BE-002/004/005 candidate: exact native account resource at owner approval

Five actual gateway counterexamples reproduced delayed owner approvals overwriting or deleting newer account state, an approval for an absent alias replacing a later registration, a native update between gateway verification and dispatch, and a changed credential file failing to invalidate an older approval. The real device/A4 routes now refuse these requests before the local writer changes that resource. This is a partial source milestone, not acceptance of the whole account, identity or operations programme.

The device's existing action HMAC stays unchanged. The opaque A4 challenge includes the current native account resource version, and the gateway recomputes that version when verifying the owner proof. Android already signs the returned challenge inside its existing CryptoObject path; no new frontend, server-address setting or manual owner step is introduced. The server supplies the version separately to the native writer. A device cannot supply that internal field. Both actual LocalAccountControl and signed Commander HTTP mutation ingress require it; the native writer checks it again under the shared account-operation lock before entering the handler. The internal `account_revision` command is gateway-only and is not a new Android owner action.

The existing registry file retains a per-alias `resource_revisions` map. Every current native add, replace, remove or credential touch advances its account generation. Removal retains the tombstone, so recreate/remove cycles and a temporary edit restored to the same visible fields do not restore obsolete approval. Disjoint account changes do not invalidate another account's pending proof. Whole-file saves and same-account stale writers compare the loaded generations. Malformed or exhausted counters refuse without replacing the previous file. Failed atomic swaps restore the previous local cache and generation.

The opaque version also binds the registered account fields and credential-reference file generation (device/inode/size/mtime/ctime). Computing it never reads or hashes credential values. Controlled credential writes advance the native generation before their atomic file replacement; a failed write may invalidate an old approval while retaining the complete previous credential. This version describes local native configuration, not a provider quote, exchange ETag, broker entitlement or financial settlement. Raw environment-variable changes, privileged rollback/restore, old writers and cross-host identity migration need their original qualified lifecycle procedures. The new counter metadata is additive to schema 1; activation must quiesce old writers and qualify migration/restore rather than treating the legacy fallback as a rollback certificate.

All registry mutations now use the account-operation lock, including callers outside Commander. The existing private persistent kernel lock is reentrant within one thread and exclusive across threads/processes; this avoids nested-flock deadlock while closing the writer race. A fork resets inherited thread bookkeeping and must acquire its own kernel lock. Native CAS/registry locks use the same resolved registry path, including a configured symlink. The kernel inode remains persistent and permission/symlink checks remain intact. Linux threads, spawned processes and a real fork are exercised; Windows is not qualified by these tests.

OAuth owner/broker checks precede native resource lookup. Consumed pending material does not hide an existing link result: historical owner metadata permits result recovery, while the existing effect reducer still verifies the original request, encrypted receipt and current device ownership. Unknown effects remain unknown and cannot be replayed. Invalid aliases and another device's state now refuse during preflight; the source helper explicitly expects those refusal statuses and continues to require 200 for valid challenges. A native version-read failure returns REFUSED/no-dispatch without exposing its private diagnostic. Exceptions after delegation retain their original uncertainty semantics.

The packet passes 1,926 full trading tests without skips using real PostgreSQL and pinned DDS source, and 91 audited gateway tests with no forbidden checkout storage opens/creation. Seven induced faults are detected after a passing 38-case control, including both independent fork-reset guards removed together; source bytes are restored. Native HTTP missing/malformed-version refusals, cold reads, disjoint writes, ABA/tombstones, failed swaps, overflow and credential-value nonaccess are covered. The original 374 mutation identities/383 edits remain unchanged.

A separate frozen backend/contracts audit at source `79a4a56f` finished 6,609 passed, 166 skipped and one failure: its existing all-HTML-escaping guard rejected a static callback title. The current source escapes that title; all four original callback escaping tests pass without weakening the guard. The failed broad result is retained in `SOURCE_QUALIFICATION_79a4a56f.json`, distinct from this packet and from its passing hosted emulator/mutation evidence.

This does not implement durable generic account-operation/result recovery, provider-side resource versions, device key/epoch binding, the full resolved-intent owner review presentation, cross-host runtime revocation, or exposure/funds/lease-safe unlink. Secret/key issuance and remote demo creation after a lost reply need their original native operation identity and reconciliation. Local unlink still cannot be called remote closure. Product-specific order/protection/settlement, CEX/funds, policy evolution and all original independent/live/production/handset gates remain required. Continue those source packets; no original feature or acceptance identity is retired.
