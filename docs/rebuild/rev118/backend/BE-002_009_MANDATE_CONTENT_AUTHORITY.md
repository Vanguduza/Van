# Full effective mandate authority

Candidate source work for BE-002 and BE-009. A real owner token for the previous `<mandate_id>:<version>` subject admitted unsigned changes to account, venue, mode, instruments, strategies, risk, loss/count limits, weekend permission, expiry, drawdown and strategy budgets. Thirteen source counterexamples include an actual kernel approval and paper fill above the owner's original limit.

Current standing admission requires `mandate-v2:<SHA-256>`, produced by `vati.risk.mandate.mandate_subject`. Signing and loading use one effective-policy parser. The subject covers all effective dataclass policy fields, including optional defaults, normalized exact decimals, account/venue/mode, instruments, strategies, bounds, lifetime and temperament selection. Token strings, signature receipts and the runtime admission marker are excluded from their own signature. Unknown input fields are refused; notes belong outside the JSON payload. Decimal normalization removes insignificant trailing zeroes without rounding through the ambient decimal context.

After actual registered-key verification, the returned frozen mandate carries its admitted content subject. The real RiskAuthority and execution router independently check that the current policy still matches it. Mutating a nested allocation mapping or replacing the mandate does not transfer the old grant. A fresh signature can admit an explicit changed policy within the unchanged platform ceilings. The optional temperament grant remains independently required. A standing policy cannot outlive its owner token.

Identity-only tokens are historical evidence, not current authorization. No migration, server signature, default key or automatic upgrade is supplied. Immutable historical events and prior qualifications remain readable and unchanged. A current policy needs a genuine owner content signature before activation; that existing owner/native gate is not issued here. This does not establish live key-revocation propagation or financial/provider acceptance.

The source example now conforms to the closed input shape; its explanatory note moved to `trading/examples/README.md`. Its placeholder is still rejected. The public key registry remains empty and every other act is unchanged; only the obsolete mandate subject description is corrected under the separately recorded bounded repair authority.
