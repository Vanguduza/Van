# VAN-ML-PKT-005: native catalog vintages and pinned bar source windows

Status: candidate source component; ML005 and BE-008 remain IN_PROGRESS. No DatasetManifest admission, complete unit acceptance, research entitlement, provider qualification or order authority is issued.

The existing independent cTrader market reader can request the actual pinned ProtoOASymbolsList protocol with includeArchivedSymbols=true. It authenticates on its own read-only connection, checks exact account/environment and connection identity, retains hidden/omitted-visibility/archived entries and rechecks its shared native I/O budget after parsing. It never creates execution contracts from these records or changes the protective adapter's active registry. NativeSymbolContract continues rejecting disabled instruments.

NativeSymbolCatalog retains canonical original decoded metadata, request profile, receiver clock and actual pinned protocol-file digest. Native IDs remain scoped to provider/environment/host/account; display names are not identity joins. Optional proto2 enabled omission remains false with explicit provenance. Unknown names and bounded multiline descriptions remain data. Archived native last-update time is preserved and is never invented as a delisting effective time. Invalid/duplicate/cross-scope identities, incompatible payload types/protocol digests, future native archive timestamps, malformed fields or self-declared qualification refuse.

NativeCatalogStore reuses the actual SQLite/PostgreSQL ledger writers in a dedicated source-only ledger. Mixed event kinds refuse. Publication binds stable request identity, exact capture, per-scope ordinal/previous original, native receive time and first durable availability. Original receipts are independently reread before completion; replay does not renew clocks or append. NativeCatalogCollector closes the independent reader before entering storage, resolves original requests before reading again, and reconciles an uncertain publication only against matching original durable bytes. Missing/corrupt/hidden receipts and conflicting requests remain unavailable; source queries do not authorize financial effects.

NativeBarWindowReader consumes the existing original native bar archive. Both an exact revision/reference and an as-of cutoff are required: later equal-millisecond captures cannot change a pinned prefix. Per-bar corrections retain their actual source revision/reference, contract identity, receive time and durable availability; every selected original is independently resolved during verification. Partial query-boundary bars are excluded explicitly. Pagination, spread, tick-volume and calendar uncertainty are preserved; no complete schedule coverage, zero spread, licensed research use or execution permission is inferred. Source, output and row budgets refuse rather than truncate. No duplicate raw bar lake or grant format is introduced.

Tests exercise actual framed protobuf peers, source files, SQL writers, separate processes and independently opened PostgreSQL connections. The first disabled-instrument fixture attempted to construct an execution-only contract and was corrected to an appropriate metadata-revision fixture while adding an explicit disabled-execution refusal. Separate catalog tests cover actual archived/hidden data. Two actual native payload failures exposed named enum decoding; both exact native enum representations now validate. A real cross-account byte-budget regression appended before the global refusal; publication now checks all source bytes before appending. The original failure reports remain. A command using a nonexistent test filename ran no tests and is retained as a harness error. The original broad run's threaded-fork warning led to a spawned-process replacement and final database rerun.

Evidence belongs to receipts/NATIVE_DATASET_SOURCE_20261026.json and ci/native_dataset_20261026. Supplemental source faults remain separate from canonical374. Canonical package bytes, requirement/action/acceptance identities and original frontend contracts remain unchanged.
