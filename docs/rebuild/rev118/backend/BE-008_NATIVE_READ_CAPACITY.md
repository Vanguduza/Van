# BE-008: cumulative native market-read capacity

Status: source-tested component; no complete unit or production capacity acceptance.

Independent native market reads now reserve cumulative capacity before reading each admitted protobuf body. All incoming frames count, including heartbeats and correlated replies. Defaults are 4,096 admitted frame headers and 16 MiB of encoded bodies per transport operation. Explicit positive integer capacities allow up to 65,536 frames and 256 MiB. The existing per-frame cap remains independently enforced. These are implementation resource limits, not provider maxima or measured service sizing.

An excess header latches an exhausted state and retires its original connection before waiting for that body. Pending calls wake with an explicit source error. Already captured financial deliveries retain their original payloads for reconciliation. The refused body was not read or decoded; no financial refusal or completed provider action is inferred. Drain, close and reconnect cannot refund this transport's original frame or byte reservations. The market-reader interface accepts explicit limits and exposes a copied diagnostic snapshot. WITHIN_LIMIT describes resource accounting only; it does not assert healthy, fresh or qualified data. An admitted header is not a decoded delivery.

The ordinary financial transport retains its original policies; this packet adds no financial dispatch or retry behavior. Total process memory, decoder amplification, rate limits across new collectors, arbitrary host code, service-wide backpressure, durable source/error journals and host isolation still require qualification. Encoded accounting excludes the four-byte length prefixes and is not an operating-system memory boundary.

The final selection passes 982 unique native/account/funding/execution cases against actual pinned isolated PostgreSQL, with no skips or storage-audit violations and exact source hashes. Focused integration passes 113 cases; final capacity controls pass 24; all 108 rebuild checks pass. Three supplemental faults are assertion-caught without setup errors and source is restored exactly. The original 374-case registry is consistent but was not executed on this local-only packet.

Initial missing-API failures are capability specifications, not 20 production bugs. The first implementation has one retained incorrect oracle: it invented false for an optional native field whose absent value the pinned codec preserves as absent. Only that expectation was corrected. The first PostgreSQL attempt stops during schema setup after pg_isready, without functional assertions; its failed receipt remains. The retry proves an actual SQL response over TCP before schema setup and execution. Owned containers are removed and client processes waited; daemon-owned shim zombies under non-reaping PID1 are observed separately, never killed or presented as reaped test children. The worker's actual child/thread probes remain healthy.

No full BE-008, source/provider entitlement, independent/native/F15/BG-001, production/economic or S24 acceptance is issued. Durable quote capture and the remaining canonical backend obligations continue.
