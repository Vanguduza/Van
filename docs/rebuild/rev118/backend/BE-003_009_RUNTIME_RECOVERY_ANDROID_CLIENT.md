# Android clients for exact native runtime recovery

Candidate data-layer wiring for the existing backend contracts. No screen or visual redesign is introduced; BG-001 and the original programme remain unchanged.

`VanGatewayClient` now provides the catalog, current state, challenge, original request and original-operation read endpoints. It uses the provisioned gateway/mTLS/device proof machinery, including the full query target for state reads. No additional in-app host configuration is needed. All five methods are recorded as client extensions of OF-TRADING-005 / van.trading.halt; UI consumption remains pending.

`RuntimeRecoveryProtocol` freezes the exact account, device, session, action, state hash, issue time and permitted argument keys. It verifies the returned intent/review/action and reconstructs the entire native A4 canonical statement before biometric signing. Six fixtures generated by the Python implementation cover all three actions and Unicode sessions. The caller signs that exact canonical statement using the existing biometric P256 approval mechanism. It passes the resulting standard Base64 signature without regenerating the original timestamp or target. The client refuses malformed signature encoding and new expired/stale intents before saving a dispatch identity.

`RuntimeRecoveryOperations` commits only public original IDs, device/account/session/action and a body digest before network dispatch. Arguments, signature and credentials are not stored. A shared process lock prevents different client instances from losing an identity during concurrent preference updates. Exact original retries retain the original ID/body; another approval for that account waits for original readback. Unknown, requested, pending dispatch, HTTP errors, corrupt history and failed writes retain the original. Only a matching native final receipt with a strict false entry-authority flag and valid native effect/refusal evidence finishes local tracking. APPLIED is not permission to trade.

Cold recovery reads the original ID. A GET does not submit or resume work. The gateway durable dispatcher now resumes saved original receipts and the native journal can certify an expired, never-accepted original as a no-effect refusal; see `BE-003_009_RUNTIME_RECOVERY_OUTBOX.md`. Its unknown current risk fields remain explicitly null. The client does not manufacture a new approval or a no-effect assertion. Native device-key revocation propagation and coordinator controls remain separate backend obligations.

The source receipt records actual Kotlin/app tests, APK assembly, lint and induced-failure checks. Hardware biometric behavior, production provisioning, deployed service connectivity, S24 and entire-unit acceptance remain unqualified by these source tests.
