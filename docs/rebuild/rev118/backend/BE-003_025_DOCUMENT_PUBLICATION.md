# Versioned document publication and original local outcomes

The existing document and artifact services now coordinate file publication with their native SQLite store. Private bytes are flushed before metadata commits. A document row, its canonical artifact and a minimal publication witness commit in one transaction. The witness contains resource identities and hashes, not another copy of the owner's PDF values. This is evidence of a local commit, not an authorizer or permission to upload or submit the file elsewhere.

A definite failed transaction or task cancellation removes only its newly created, unpublished copy. It cannot remove a previously published version reused by an identical replay. A lost commit acknowledgement is reconciled against that exact transaction witness. The caller receives its original version even if another writer has already saved a newer one. Unavailable readback preserves the bytes and returns `DOCUMENT_PUBLICATION_UNKNOWN` with document/publication identifiers. The paired owner API and existing scoped Gmail adapter preserve this distinction.

Canonical artifact lookup/create is serialized and includes the native owner. It cannot adopt another owner's private card or silently change a projection's sensitivity. Repeating the same canonical output reuses its artifact. Different output hashes have different immutable references and complete-digest filenames. The existing content endpoint accepts a strictly validated `sha256` query to retrieve the exact published version. Missing, expired or `SECRET_REF_ONLY` versions cannot fall back to the latest copy. Legacy short-digest filenames remain readable when the complete digest verifies.

Partial edits start from the verified current copy, merge the requested values and render all merged values from the immutable original source. Actual output fields are verified and committed with the new version. Concurrent edits retain one another's omitted values. Field inspection reparses the verified current PDF, including legacy records whose cached values were stale. An optional `expected_proposal_sha256` binds the review to the current baseline and values inside the write transaction. Supplied context identifiers must match the original document. Empty final values remain disclosed as missing, with required fields identified separately.

Evidence: `receipts/DOCUMENT_PUBLICATION_SOURCE_20261023.json`. It records reproduced document/owner-scope failures, original-result/commit-refusal/readback-unavailable checks, actual task cancellation, paired gateway and Gmail routes, legacy/cache/version checks, 224 integrated cases across document/artifact/mission/control/Google paths and seventeen deliberate fault/control pairs. An initial deferred-lock mutant survived ordinary timing; the retained attempt led to a controlled independent SQLite writer in the real read/write gap. The corrected oracle rejects that fault.

These are candidate source guarantees. A process or host failure before the SQL commit can leave an unreferenced private file; a crash reaper and complete erasure/retention graph are still programme obligations. This packet does not add client request IDs to every CRUD operation or claim recovery after every lost first HTTP response. Versioned local output does not establish external submission, provider execution, physical PDF rendering, whole-unit, production or S24 acceptance. The original programme and independent/native gates remain unchanged.
