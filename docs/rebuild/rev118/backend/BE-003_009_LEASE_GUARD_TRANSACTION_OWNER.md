# Preserve the outer runtime-lease submission lock

The existing PostgreSQL lease store rolled back its private connection after every read and every guard exit. A nested read, the runtime fence that calls that read, or an inner guard therefore released the outer `FOR UPDATE` row lock before its submission scope ended. An independent actual PostgreSQL actor could take over the expired timestamp while that scope was still active. Three baseline cases reproduced, with a positive control that observed the peer waiting on an actual database lock. This is source arbitration evidence, not a claim that a native trade occurred.

The private store now has one reentrant connection/transaction owner. Same-thread reads and inner guards borrow the outer transaction; other threads wait for that owner. Only the outer exit releases its locks. Reentrant mutation and close refuse before touching authority. Body failures retain their original exception. No lease key, logical alias, public field, owner grant, CAS or epoch rule is replaced.
