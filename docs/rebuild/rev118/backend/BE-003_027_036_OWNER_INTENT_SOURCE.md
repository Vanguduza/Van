# Owner intent source, replay and privacy

Owner goal observations now require the actual native mission, matching direct owner-command authority, owner device principal, origin/channel, effective action class and original native context. A source label on an arbitrary mission cannot supply that evidence. Automatic and scheduled work cannot manufacture repetition of an owner goal. Approval learning uses the same read-only evidence loader, with its additional approved A4/A5 constraint. The post-seal command join observes the original mission after authority exists; learning never issues authority.

Each native mission receives one minimal projection receipt in existing runtime metadata. Its opaque mission/intent identities, scope hash and native revision commit in the same SQLite transaction as the node, observation count and mission link. Replays preserve the original identity and count, including concurrent delivery and a lost commit acknowledgement. A rebound or malformed receipt is refused. Existing native links can acquire a receipt without recounting their observation.

Native owner erasure witnesses are read inside that transaction. Exact identity tombstones prevent a replay from attaching an old mission to a newly created same-text goal. The existing context revision barrier holds an old delayed source after bulk deletion, even when the store was empty. A delayed source with no original identity is conservatively held after selective deletion too. Fresh post-erasure consent remains learnable; no clock ordering substitutes for native revisions. Erased goal text, constraints, nodes, edges and mission links are not copied into the receipt. The owner memory inventory explicitly discloses the minimal receipt retention.

Integration exposed a separate production readback bug: the observed-pattern reader accepted only historical `owner` principals, whereas real command missions use `device:<id>`. It now recognizes that native identity and validates approval source/context within the same coherent read snapshot. Tampered principals, automatic origins and changed context commands/digests stay unmeasured. Explicitly answered owner decisions retain their own existing authoritative answer checks. Patterns remain bounded observations, with counterexamples and unknown outcomes; they do not establish a causal reason or grant execution authority.

Historical tests were corrected to construct real native context/authority rather than self-described approval records. Two classifier tests explicitly seed legacy unverified observations to retain their read-side rejection checks. The post-insert mission-write regression now induces a required native event failure; optional learning failures retain their separate availability tests. The original eight integration failures and intermediate three remaining failures are retained as evidence, rather than counted as passes.

Validation is recorded in `../receipts/OWNER_INTENT_SOURCE_20261024.json`. No migration rewrites historical inferred counts or upgrades legacy evidence. Durable retry/drain of optional learning, complete feedback recovery, further memory producers, complete unit acceptance and live service/provider/device qualification remain separate programme work. No endpoint or frontend is added, and no F15/BG-001 certificate is issued.
