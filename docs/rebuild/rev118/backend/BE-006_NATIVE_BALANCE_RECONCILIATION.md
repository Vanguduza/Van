# Native deal history and balance reconciliation

This is another BE-006 source component. It preserves the original programme and is not whole-unit acceptance or permission to move funds.

The native cTrader deal collector uses the published request/response protocol on the separate read connection. Inclusive timestamp windows are bisected when a page is partial. Saturated single-millisecond pages, changing duplicate facts, missing parent facts, foreign account identities, invalid row precision and resource limits reject the whole window. Native identifiers never become an assumed economic order. Missing closing fees, balance versions and conversion fees remain unknown. This is a financial reconciliation subset, not a full execution-history export.

Cash and deals have distinct append-only observation kinds and independent catch-up cursors. Original identity, availability and conflicts survive retry, concurrent collection, restart and lost commit acknowledgement. A failed deal read cannot advance its cursor through a successful cash window. Provider notes and raw authentication errors are excluded.

Both existing runtime snapshot producers now persist the current native mark separately from the older background collector result. Receipt time is taken after the native I/O completes. The owner projection binds the current native profile and reads marks, cash and deals within one repeatable read snapshot. SQLite readers do not reserve the financial writer; PostgreSQL uses a repeatable, read-only transaction. Append/atomic writes during an outer read transaction are refused. Existing surrounding writer transactions retain their rollback behavior.

A native period requires original producer-bound marks, complete cash/deal query coverage, unique and gap-free native balance versions, cash amount/post-balance agreement, closing deal post-balances and consistent intermediate marks. Invalid, conflicting or incomplete evidence produces an explicit refusal. The latest observed knowledge watermark does not claim that later-collected history was known at trade time.

When no external capital crossed the period, native net marked equity supports a marked-account return and drawdown over all observed samples. This is not intraperiod extrema, settled trade PnL, causal attribution or strategy alpha. When capital crossed the period, historical total equity still lacks contemporaneous restricted-credit state; percentage return stays unmeasured. Reconciled dollar PnL subtracts native external capital, and separate IB/management business income is also exposed separately. A deposit and an IB commission cannot become trading profit. Closed-trade commission allocation, sign conventions and settlement are not inferred from post-balances.

Existing paired-owner accounts/portfolio routes expose bounded native deal previews and the period evidence. Android receives exact monetary/native-ID strings, original availability, basis, qualification and unknown states through existing account SDK models. No screen redesign, new financial-effect endpoint or execution authority is introduced. See [the owner contract](FUNDING_OWNER_READ_CONTRACT.md) and `../receipts/NATIVE_BALANCE_RECONCILIATION_SOURCE_20261024.json` for actual checks and their limits.
