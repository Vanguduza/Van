# BE-008: native frame and read-operation budgets

Status: candidate source component; no complete unit, capacity or provider qualification.

The transport no longer waits for an arbitrary unsigned32-bit payload length. It refuses zero/over-capacity frames before reading their body and uses a bytearray for fragmented receives. The default implementation capacity is8MiB, with an explicit validated1-byte through64-MiB setting. This is a resource limit chosen by the implementation, not a claim about a vendor's protocol maximum or a qualified deployment's capacity. Native frame failure after an order request remains UNKNOWN and never permits another send or a fabricated refusal. The financial receipt's existing generic uncertainty/privacy text is preserved.

The independent market reader now uses an explicit read-only transport. Only application/account authentication, symbol list/detail, trendbars and heartbeat requests are admitted. Financial, protection and unknown operations are refused before connection; bounded entry is always refused as not sent. Ordinary financial transport peer and caller-response timeout behavior is preserved.

One monotonic operation deadline covers native connection return, TLS/socket I/O, response waiting, the actual send mutex, successive calls/reconnect and final observation parsing. The default native-read budget is30seconds; explicit positive finite budgets through300seconds are supported. The clock cannot move backwards or become an invalid value. A queued response, later call or reconnect cannot renew the original deadline. Socket waits and send-mutex waits are clipped, expiry is rechecked immediately before a source write and after the response/observation parse, and failed source calls close their owned reader. Selected-product collection and native contract checks remain intact.

DNS resolution, arbitrary custom connector/clock code, OS scheduling and archive persistence are not an interruptible host sandbox. Elapsed connector work is charged and expiry checked on return; a separately governed/reaped worker still must bound uninterruptible host work before production qualification. No hard wall-clock guarantee for those phases is claimed, and no background production source worker is activated by this packet.

A further actual cleanup race was reproduced: a failed reader detached itself before completing socket release, so close could return without joining it. The transport now retains exact reader ownership until termination/join. Close snapshots only existing owners and cannot join or close a later replacement; failed thread creation and reconnect prune their own references. Original pending-call wakeup, uncertainty and replacement-isolation contracts remain.
