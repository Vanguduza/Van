# Physical account arbitration continuation

Inspection only; no physical-account lease or native exposure qualification is issued.

The active account registry permits multiple aliases for one native account. Existing runtime leases and owner/recovery state use the logical alias. The earlier persisted-registry/InMemoryLeaseStore probe was primitive-only; no end-to-end native financial bypass is established. The actual cTrader factory uses `int(account.login)` and chooses its official transport host from server/demo metadata. Native account identity, provider/realm/host, logical alias and verified observed account binding are distinct concepts.

Preserve logical alias arbitration as well as any additional physical-account arbitration. Simply replacing alias keys can allow two different physical accounts with the same alias to collide in alias-scoped financial/recovery owners, and can invalidate signed controls. Multiple observer/profile aliases remain valid. Inspect all sending runtime constructors and final submission guards, canonical broker identities, epoch/state bindings, retirement/recovery and the admitted cohort before implementation. MT5 and MT5_EA may address the same underlying account; Deriv client app identifiers do not identify separate customer accounts. Do not infer identity from currency, a display name or an arbitrary digest.

The PostgreSQL connection-owner repair in BE-003/009 is a prerequisite for composing guards: a nested read/guard previously released its parent lock, and real SQL errors required native savepoints. Complete its committed qualification first. Any later physical scope must preserve alias fencing, current owner authority, safe expiry/takeover/release, account-wide financial lineage and explicit old-cohort migration/unknown-effect holds. Provider proof and independent/native admission remain separate. No new owner authorization, grant format, frozen-package amendment, registry rejection or frontend design is created by this note.
