# Spoken-result queue and playback admission

Six JVM counterexamples reproduced lost first sentences, skipped unfinished audio, interrupted audio acknowledged as heard, premature completion and conflicting response/segment identities. Three gateway controls reproduced inconsistent initial cursors, interrupted streams still resumable through the direct method and an empty provider chunk removing the final marker.

The existing application path now actually joins VanCommandController → VanSpokenAnswer → VoiceEdge's queue → the selected offline engine → VanApplication callbacks → the exact queued segment. Offering text does not mark it spoken. The queue advances only its contiguous spoken prefix, retains interrupted/failed terminal states, distinguishes no audio heard (`-1`) from segment zero and refuses duplicate/conflicting indexes and response identities. New unheard continuation cannot inherit an earlier final marker. No redesigned frontend was added.

Native playback has a separate unique attempt ID even when a logical segment ID is reused. Late start, frame, error, stop and done callbacks cannot mutate a newer utterance. Completion requires an admitted start. Pending synthesis is cancelled before owner recognition begins, using the actual VoiceSessionCoordinator, rather than only interrupting audio already marked speaking. Application queue callbacks are marshalled to the main thread and each VoiceEdge delivery also has its own identity, so delayed callbacks cannot acknowledge a replacement response.

Sherpa's streaming AudioTrack now drains to the submitted frame count before completion. A successful write into the buffer is not proof of playback. Cancellation, a stalled head or a regressing head cannot produce a spoken acknowledgement. This verifies native progress, not a claim that a human listened. Android fallback stop/error handling also retains the unplayed distinction.

Verification: **1,290 JVM tests**, **195 app unit tests**, debug and instrumentation APK assembly pass. Lint reports zero Error/Fatal and 89 warnings; the inspected warnings in modified files are inherited SDK/KTX suggestions. Forty-eight backend voice/speaker/synchronization tests pass. Seventeen new JVM cases and three new backend cases are included. Three affected legacy mutations are assertion-detected after a passing control; sources are restored. All 374 original identities remain, now 383 edits because replay admission has two independent guards. The public source CI job independently executes all 48 backend voice cases with a zero-skip guard; the private DDS key gate is unchanged. Sixteen CI contract checks pass. Source and artifact digests are in `receipts/SPEECH_CONTINUITY_SOURCE_20261022.json`.

Two new emulator tests compile against the real application, pinned generic offline model and AudioTrack: actual answer-to-spoken queue acknowledgement, and an actual owner-turn cancellation followed by a successful replacement. They have not run locally because this environment has no emulator/KVM. Hosted execution is required; neither compilation nor the older 16 passing instrumentation cases is substituted for that result. The original voice bundle pin and artwork remain unchanged; only temporary owned debug fixtures were staged and removed for local builds.

BE-029 remains partial. The gateway SpeechStreamService still lacks its real command-result producer and authenticated cursor consumer, and its streaming finalization, device binding, retention and process-recovery contracts need full closure. Current actual spoken command outcomes use the local application path described above. Delayed polled answers still need current owner-context admission, and call/audio-focus deferral needs its real resumption policy. Native provider/service, production signing/provisioning, independent unit admission and S24/Artemis evidence remain distinct. No in-app configuration, financial authority or release gate was introduced.
