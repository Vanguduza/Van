# Device-bound command and speech result foundations

Three real HTTP counterexamples demonstrated that another paired device could read a mission-backed command result when its audit row was absent or its latest audit observation had no device. The mission's durable owner principal is authoritative; missionless refusals are selected only from the calling device's audit rows. Unrelated audit observations cannot transfer ownership or remove the genuine owner's access. The genuine owner still reads the result in both cases; a foreign device receives the same 404 as an unknown command. This closes a prerequisite for serving those results as speech.

Twelve service counterexamples also reproduced shared speech queues across devices, silently changed retry inputs, impossible cursor acknowledgements, expired cache reads and empty unfinishable responses. Speech stream identity now binds the device, response and exact original request content; exact retries preserve progress, conflicting inputs refuse, and the same input after a process restart retains its identity. Changed content cannot alias old audio. Cursors must be actual integers in the served range, with spoken progress no later than received progress. Existing 24-hour retention is now enforced on access as well as by explicit sweep; no retention duration or financial policy was changed. These remain presentation facts and grant no command authority.
