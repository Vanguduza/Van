The existing native trendbar reader now validates the actual response type, native account, product and outer timeframe. Requests have strict integer windows and bounded counts. Present native fields use their actual signed/unsigned integer ranges; malformed values, impossible OHLC, duplicate samples and outside-window data are refused. Open bars are excluded against both the requested end and actual post-I/O receipt time; future observations are refused. The deprecated server timestamp cannot redefine the original request.

The additive immutable observation records original native account/product, timeframe/window, receipt time, transport host, native contract revision, pagination and the exact bar values. Unknown pagination remains unknown. Trendbars have no spread: the observation reports null and an explicit unavailable state. The legacy Bar adapter retains its existing mandatory zero spread placeholder, which is explicitly not measured spread. Fixed-duration endpoints derived from native open minutes remain an unqualified calendar representation; broker sessions/DST and authoritative live closed-bar semantics still require the full native producer programme. No HTTP source-fact injection or live monitor activation was added.

Native symbol discovery verifies response types and account scope, distinct native IDs, complete requested details, collision-free aliases and actual mandatory digits/lot/minimum/step/maximum values. There are no guessed contract limits. One complete registry is published atomically. Each complete contract carries a deterministic revision tied to the original native metadata and transport scope.

## Protocol preservation

The pinned [ProtoOATrendbar definition](../../../../trading/vati/execution/ctrader/proto/OpenApiModelMessages.proto) uses optional price deltas. The [official protobuf proto2 guide](https://protobuf.dev/programming-guides/proto2/#default) specifies default values for unset scalar fields; the [cTrader symbol-data guide](https://help.ctrader.com/open-api/symbol-data/) describes native relative-price reconstruction. The reader supports valid zero defaults for absent optional deltas and records exactly which fields were defaulted. Application price/time coordinates remain explicit. A draft test that treated every missing delta as a corrupt market fact was corrected against these primary contracts; the original failed attempt remains retained. Malformed provided fields and incoherent prices still refuse. No provider code was copied or new dependency adopted.
