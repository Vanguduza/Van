# Public-source qualification on four isolated workers

This candidate changes the existing public-source verification instrument and its workflow ownership, not product scope or native authority. `backend-public-source` remains the required job ID and displayed gate. All other jobs, triggers, admission checks, global concurrency, credentials and the 374-case mutation corpus remain unchanged; the workflow installer mirror stays byte-identical.

Four fresh Ubuntu24.04 workers each have the original pinned PostgreSQL17.11 container/schema, locked gateway dependencies, Node24.19.0, real Chromium and separate temporary test storage. Each runs one pytest process. There is no shared database between workers and no xdist or parallel pytest processes inside a worker. The original explicit selected-file roots, separate/private/browser exclusions and exact approved-skip vocabulary remain. Every collected class/parameter identity remains in scope; costs never decide inclusion.

The ordinary pytest collection produces exact nodeIDs before whole-file deterministic assignment. Historical measured file durations apply only when the current test-source hash matches the recorded source. Changed/new files use their collected case count as a deterministic placement fallback. Files stay together, ties use path and worker index, and test order inside a file remains pytest's order. Four workers must agree with the required gate's independent full collect-only control. Collection errors, selectors, inherited pytest override flags and shared-store parallelism cannot silently reduce the inventory.

Each execution captures real setup/call/teardown reports, exact nodeID properties in JUnit and the unchanged storage audit. Parent command observations independently bind the expected GitHub head, clean tracked source/tree, software/package/image/Chromium identity and actual isolated PostgreSQL version before and after pytest. A fresh execution nonce binds the parent receipt and child evidence; workflow run and attempt must match. Original evidence folders cannot be overwritten. Partial, stale, collection-only or status-only artifacts do not qualify. Teardown failures count as failures even when the call passed. Every skip requires its original exact case/reason approval and remains declared unexecuted rather than passed.

The existing required gate waits for all four execution workers with fail-fast disabled, then independently validates collection/assignment and the exact execution union. Missing, foreign or duplicate IDs, absent shards/artifacts, unsuccessful/nonterminal receipts, wrong source/environment/run identities and storage events fail the aggregate. The separate media runtime still uses its own hashed lock/venv and independently collected/executed exact identities. Existing named artifact and runtime-report fields remain available; combined gateway reports are explicitly derived from four verified shard reports, with original reports retained. They are not a single-process full-suite run. There is no fallback from the required gate to legacy module-count verification.

The first independent source review found that checking only tracked Git changes missed an untracked collector: a real eight-case committed fixture became four cases with unchanged HEAD/tree. That failed review and its original archive remain historical evidence. The repaired input boundary inventories both ordinary and ignored untracked files, including data read by tracked parametrizations, and refuses additions outside narrowly named inert public-source evidence files and pytest cache data. It never treats `.gitignore` as source authority. Any repository bytecode present before a new run is refused, even if it compiles from tracked source. Instrument processes suppress writes, but unchanged tests can launch isolated children that create caches. Only after the child exits, the separate parent checks each new cache against unchanged exact tracked source, current-interpreter header/optimization and a fresh compilation of every code field and typed constant. Cache code is decoded only as verification data, never imported or executed; legitimate frozenset wire ordering across hash seeds is normalized while forged code is refused. The parent archives exact verified bytes in a mandatory non-importable JSON artifact, rechecks their hashes, then retires only those absent-before generated files. The aggregate independently repeats this proof. Unknown source/config/data and preexisting cache inputs remain forbidden; owner files are not broadly removed. The committed root `pytest.ini`, effective root/conftest boundary and original import roots are explicit. Ambient plugin loading is disabled and replaced by the actual original locked runtime plugins: gateway uses asyncio and anyio; the separately hashed media runtime uses asyncio only. Installed pytest entry points must match those original sets, and effective plugin code/config hashes must agree between each runtime's independent collection and execution. A different plugin set, import root or optimized Python process fails closed.

Native qualification requires the future exact-head hosted execution. Local tests exercise the verification instrument with explicitly synthetic protocol fixtures and tiny real pytest subprocesses, including an actual teardown counterexample, collect-only controls and isolated media dispatch. They are not application test totals, native four-worker execution or performance evidence. Current source construction issues no native/unit/BG001/provider/device/signing/deployment/release certificate; private DDS and other original mandatory gates remain separate and unwaived.
