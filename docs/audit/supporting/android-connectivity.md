## Remaining limitations and external acceptance gates

1. **Actual owner device and live services remain unverified by this agent.** StrongBox/Keystore certificate chains, the installed production signing identity/trusted attestation roots, installer delivery, direct server SAN/CA, TLS listener/firewall, actual Hermes work, browser SDP/ICE/TURN/media, Google/DIAL credentials and hosted service effects require the coordinated live acceptance run. A compiled APK and fake transport tests do not establish those effects.
2. **Totally new private CA anchors remain fail-closed.** Signed endpoint and SPKI rotation can use the installed private CA or platform CA trust. A completely new private CA needs an authorized build or a separately defined signed CA-anchor contract; a pin is never a trust-any-server bypass.
3. **Legacy lost first pairing replies cannot be recovered from token hashes.** Newly prepared candidate-token enrollment is recoverable. An older attempt whose server-generated token never reached the device needs fresh installer enrollment authority; no shared credential or used-ticket-only recovery was added.
4. **A4/A5 process-death outcomes remain explicit uncertainty.** Those messages intentionally never persist. An already-buffered authority-bearing live request can die before its answer; gateway status/owner recovery must resolve it. A3 remains reconfirmable; no invisible replay with a fresh ID is introduced.
5. **HTTP/SSE is one ingress and does not prove HTTP/2 negotiation.** The Android HTTP stack decides wire protocol; the manager uses a real Class B streaming carrier but does not claim redundant physical reachability or native simultaneous standby media.
6. **Permanent enrollment/certification refusal holds authority.** Pending setup is bounded by signed expiry; transient startup recovery currently schedules a single five-second retry worker. Existing paired certification refusal also holds sessions and can continue retrying; token/key revocation never triggers automatic identity replacement or authority minting.
7. **Final whole-app/device acceptance is coordinated elsewhere.** Earlier uncached AGP/Sherpa dependency blocks were resolved by deployment. Actual Kotlin compilation, APK generation and app JVM tests ran; final settled-source compilation/APK/lint and the x86 instrumentation package all passed in deployment-owned evidence; instrumentation execution and real-device results remain external, not inferred from compilation or the JVM harness. The CI ABI mismatch was corrected in deployment-owned build/workflow files.

No edits are intentionally unfinished in this Android assignment. Source is stable; the final aggregate harness passed and preceding whole-app checks passed; deployment is checking the post-browser snapshot. Real-device and live acceptance remain with their owning agents. All assigned focused tests, including the final peer presentation helper, have completed successfully.

## Final browser owner-control correction

**AND-CONN-11 / P2 owner-control correctness:** baseline `BrowserSessionController.kt:469–497` discards takeover/suspend/end failure; initial viewport ack at `:406` and resize ack at `:270` discard acknowledgement errors. Takeover also reads after a failed mutation, so it cannot tell the owner whether their requested control transfer succeeded. Failed close disconnects locally without confirmed remote closure; the old status and cancellation handling do not represent that uncertainty.

The controller now uses actual pure `BrowserControlMutation` for these operations. Takeover requires matching owner holder, lease ID and a newer generation in both receipt and authoritative readback. Pause/close require same-session observed suspended/terminal state. Viewport acknowledgement requires exact session/revision; confirmed proposals advance local viewport before acknowledgement, so failed ack cannot reopen input against an old layout. Unconfirmed operations retain the latest confirmed snapshot, show readable refusal or unknown outcome, and hold input until a fresh gateway state resolves authority; stale confirmed responses cannot regress generation/revision. Cancellation propagates through controls and the controller's shared result capture. Each mutator is called once; there is no unkeyed resend. Current source: controller `:92`, `:268`, `:423`, `:482`, `:498`, `:509`, `:527`; helper `BrowserControlMutation.kt:18,31,44,59,66,73`.
