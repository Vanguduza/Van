## Error-path contracts and remaining gaps

- Google: missing/expired credentials → explicit 503, action authority errors → 404/409, unsupported intents → unsupported, A5 denied, A4 approval required, CONFIGURED refuses executable planning. Workspace revoke is now consistent across status, mesh, readiness and planning. Quota refusals remain capability-scoped.
- DIAL: disabled 404; invalid request 422; upstream timeout/auth refusal/redirect/malformed/server error → safe 503 reason; upstream business 4xx preserved. Android projection reducers distinguish stale/degraded/error/empty/loading/ready, preserve expected revision, and refresh on SSE or stale-threshold poll. Stale actions cannot be silently queued. These proxy contracts passed focused tests, with no production DIAL query.
- Browser/automation: enabled/configured flags are not live readiness; live canary evidence drives READY. Android now consumes safe owner projections for runtime version/certification, dead letters, workflow health, standing authority, Temporal configuration and registered computer surfaces. Internal execution controls remain governed operator/Hermes lanes; no worker credential or raw diagnostic payload is exposed to the phone.
- Browser `worker_configured` is `worker is not None` (`browser/api.py:654`), while `create_app` always constructs HybridBrowserWorker. It indicates code wiring, not host/runtime configuration. The current Android string should not be read as live qualification.
- Browser deadline and false-success defects HS-07/08 corrected. A worker request already sent cannot be retroactively cancelled by this loop; deadline enforcement prevents subsequent actions/late completion claims once it returns. Remote transports retain their own timeout. Standalone browser task postcondition verification remains unimplemented, so owner outcome explicitly UNVERIFIED while execution status can be COMPLETED.
- Remaining trading UX coverage: no standalone owner ticket confirmation screen/client, event feed destination, market/instrument workspace, direct risk destination, broad strategy catalogue or instrument-specific chart settings beyond available screens. Existing endpoint-backed pieces remain discoverable metadata gaps, not live broker capability claims.
- Ready Google artefacts are historical repository evidence. External gates in `docs/EXTERNAL_GATES.md` remain controlling. `PROJECT_CANONICAL_STATE.json` still blocks production release at 0.5.0-dev; this audit does not alter that authority.

## Verification limitations

The 143-method appendix is source extracted, not a complete runtime OpenAPI proof of conditional mounts. Dynamic DIAL hubs and new owner projections were added explicitly; callback/security/user-bound mount conditions must accompany routes. Neither the Gateway's code presence nor a passing mocked upstream test establishes live n8n, Stagehand, Harness, Google provider, trading broker, DIAL projection, public ingress or physical S24 success. Happy/error paths are proven only for the reported local tests and concrete regressions. Broader suite/build/device counts belong to root's combined evidence report.

## Authorized owner projection and control implementation

The five new GETs are mounted through `OwnerServiceApi` (`backend/van_gateway/owner_api.py:520`, current app mount `app.py:2772`). Explicit Pydantic response models publish the real DTO and nested schemas in OpenAPI, including fixed standalone `owner_success=false` and `verification_state=UNVERIFIED`; a focused regression checks these exported contracts. They require an authenticated, still-enrolled owner device, return `Cache-Control: no-store`, and do not accept internal credentials as owner authorization. Limits are 1–100 with default 30. Missing device is 401, unknown/revoked device 403, unreadable device store 503, unknown browser task 404, invalid bounds 422. A failed source section yields safe `PARTIAL` with generic section codes while preserving independent sections. Envelope `AVAILABLE` describes the read projection only.

`automation.standing_intent.disable` is bounded A3 stop-only work (`local_executors.py:300`). The executor checks sealed signed current-device authority, retains intent/workflow/history, captures exact roots before mutation and revokes only that intent's roots. A distinct production observer re-reads committed disabled state plus captured root IDs; provider claims do not verify it. Resuming needs fresh owner authorization; no revoked root is revived.

`memory.erase` is canonical irreversible A4 (`context/memory_erasure.py:67`, executor `local_executors.py:367`). Exact owner phrases are `forget all owner-derived memory` and `forget owner-derived memory store <allowlisted-table>`. The existing challenge is bound to signed device/action/text/turn and cannot move to a different store or new occurrence. Direct `DELETE /v1/context/memory` now refuses 409 and preserves data (root change). Sealed parameters contain exact affected stores; `intent_nodes` permits only its linked `intent_edges` and `intent_missions` closure, retaining unrelated child rows. Other-principal cognitive assertions and audit/mission history remain. Witnesses store counts and exact primary-key digests, never erased content/raw IDs. Fresh independent readback proves captured IDs absent, selected scope empty, exact approval binding and persisted context revision invalidation; response counts are observed, not fabricated.

Independent review found and corrected a write-lock timing gap in the new erasure: device revocation or expiry after executor precheck could precede deletion. The transaction now rechecks current sealed A4 authority/device under `BEGIN IMMEDIATE`, checks fresh wall time before deletion and afterward, and rolls back if approval expires during deletion. Regressions exercise both pre-write refusals, mid-write rollback, correctly signed UNTRUSTED input, real populated hot-cache invalidation, scoped closure and idempotent replay. Review found no remaining blocking issue in this scope.
