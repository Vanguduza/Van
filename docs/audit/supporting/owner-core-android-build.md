## Confirmed repository defects remediated

**PKI operator revocation could remain accepted by a serving gateway.** `DeviceCA` originally loaded `issued.json` once and consulted its in-memory dictionary for admission. The documented operator CLI creates another instance and rewrites the record, so its revocation did not reach the running object. A throwaway two-object reproduction returned `same_running_object_admits_after_cli_revoke=True` and `fresh_object_admits_after_cli_revoke=False`. The documented CLI is at [backend/README.md](/workspace/Van/backend/README.md:101); the CLI call is at [pki.py](/workspace/Van/backend/van_gateway/mtls/pki.py:344).

The fix reloads the issuance record for every admission, refuses missing/corrupt authority, and reloads it before mutations. A stable owner-private `issued.lock` coordinates gateway/CLI processes with `flock`; this also prevents an overlapping issuance from overwriting an operator revocation. The record still uses its existing atomic write. Platforms without the required OS locking refuse admission and mutations instead of silently using only a thread lock. See [pki.py](/workspace/Van/backend/van_gateway/mtls/pki.py:162).

Regression coverage includes independent CA instances, lost/corrupt records, sequential issuance after revocation, a separate process revoking at the gateway's read/commit seam, unsupported locking, and a real listener that returns HTTP 200 before CLI-side revocation and 403 afterwards. Owned source files: `backend/van_gateway/mtls/pki.py`, `backend/tests/test_mtls_pki.py`, `backend/tests/test_mtls_live.py`. The first aggregate backend run had one new-fixture failure because pytest adjusted only its own import path when running from the repository root. The subprocess now receives an explicit resolved backend package path and reports early-exit stderr; all held-lock and preserved-update assertions remain. The root-cwd rerun explicitly removed inherited `PYTHONPATH` and passed all 28 PKI/live tests ([final log](/workspace/van-audit/mtls-final-regressions.log)).

**Installer-selected paths now reach the installed units.** The gateway and tunnel installers previously accepted custom roots/binaries but copied templates with default paths. A common renderer now resolves their selected paths into working directory, Python path, environment files, executable/token arguments, and sandbox path allowances; the original default layout is preserved. See [renderer](/workspace/Van/tools/runtime/render_systemd_unit.py:40), [gateway installer](/workspace/Van/tools/runtime/install_van_gateway_service.sh:74), and [tunnel installer](/workspace/Van/tools/runtime/install_van_cloudflare_tunnel.sh:34). The renderer refuses control characters, escapes systemd specifiers/arguments, and escapes the native `glob(3)` syntax used by `EnvironmentFile`. A fixed shell `exec` command handles quoted/backslash executable names without evaluating path contents. Tests run full repeated installs against isolated paths with spaces, percent/dollar/colon/quote/backslash characters, preserve existing configuration/token bytes, and validate both units with `systemd-analyze verify` plus an actual native glob probe ([tests](/workspace/Van/tests/contracts/test_runtime_installer_paths.py:86)). No real service was started.

**Same-SAN server certificates now renew near expiry, and direct-PKI expiry is monitored.** The mTLS enable script previously renewed only an absent certificate or changed SAN. It now reissues a missing, malformed, expired, or within-30-days server certificate through the existing CA CLI, retaining the CA trust anchor and issuance record; healthy repeats retain the same server certificate ([script](/workspace/Van/tools/runtime/enable_van_mtls.sh:50), [regressions](/workspace/Van/tests/contracts/test_van_mtls_renewal.py:25)). The monitor now reads `ca.crt` and `server.crt` separately from trading PKI, distinguishes unconfigured from configured-but-missing material, exposes expiry in operator health, schedules the direct-PKI scan, and emits `DEVICE_PKI_EXPIRING` without mutating PKI ([scan](/workspace/Van/backend/van_gateway/ops/pki.py:120), [health](/workspace/Van/backend/van_gateway/ops/health.py:66), [app](/workspace/Van/backend/van_gateway/app.py:745), [alert](/workspace/Van/backend/van_gateway/observability/alerts.py:318), [tests](/workspace/Van/backend/tests/test_ops_device_pki.py:19)). CA expiry still requires coordinated trust-anchor/device rotation; renewal deliberately retains the existing CA pin.

**Ledger configuration replacement now preserves its trusted existing mode independently of umask.** The reconciliation script passed the existing mode to `os.open`, but creation applied the process umask; the aggregate trading run exposed a 0640-to-0600 mode change. It now creates a unique owner-private staging file, applies the existing ownership where permitted and explicit permission bits with `fchmod`, and atomically replaces the target, removing staging files after errors ([script](/workspace/Van/deploy/van-trading-core/supabase/reconcile_vati_ledger.py:37)). This also removes the fixed `.tmp` path that could overwrite a stale symlink target. Regressions retain the existing URI escaping checks and prove both 0600/0640 under umask 077 plus unrelated-file preservation ([tests](/workspace/Van/trading/tests/test_vati_ledger_reconcile.py:36)); all seven tests passed.
