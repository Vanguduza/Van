## Command and execution trace

1. HTTP ingress middleware checks outer ingress bearer, device access token, mTLS certificate identity where applicable, and bound-device hardware proof on `/v1/commands` (`app.py:1233`, `app.py:1702`). Session delegation uses the same orchestrator. WebSocket handshakes enforce the hardware binding policy explicitly because HTTP middleware does not run for sockets; replay and ongoing token/binding revocation are checked. Device enrollment scope is separate from Hermes/runtime authority.
2. Idempotency claims exact request hash atomically; matching completed requests return their original receipt. Conflicting attempts cannot modify it (`idempotency/service.py:54`). Device/signature checks bind canonical v1/v2/v3 command fields; v2/v3 require OWNER_DEVICE principal and the matching device requester (`orchestrator.py:186`). Nonces are durable and consumed once (`command/nonce.py:42`).
3. The deterministic resolver only handles conservative known phrases; everything else remains Hermes interpretation (`command/resolver.py:76`). Effective class is the stronger of caller and canonical class. Typed/global/explicit expiry, speaker disposition, A5 refusal and exact-action A4 biometric challenge/proof run before execution. Approval is an intent-bound, device-key P-256 signature consumed in a transaction, not a decision-list checkbox (`approval/service.py:114`).
4. Effective content trust is derived server-side from origin and captured-content markers; only genuine owner input can carry state-changing intent. External/model/retrieval content remains data (`command/ingress_trust.py:101`).
5. Genuine intent creates one durable Mission. Exact actions get a registered checkable success contract; arbitrary work retains an empty contract and cannot assert verified success. Mission ladder: CAPTURED → UNDERSTOOD → PLANNED → AUTHORIZED → RUNNING after Hermes accepts; safe failure stays authorized, ambiguous acceptance waits externally (`command/mission_link.py:136`, `orchestrator.py:906`).
6. Project mutations require current cached Project Truth; context requirements seal owner evidence and surface missing/stale gaps. Client context is marked non-authoritative. The command authority binds device, original request, exact action/parameters, context snapshot/digest, action ceiling, expiry and approval (`command/authority.py:25`). At action authorization, A3+ required/extra parameters must be sealed.
7. Six gateway-local action families execute deterministically: remember owner fact, record decision, reminder creation, trading halt, standing-intent disable and owner-approved memory erasure. Each uses its registered signed authority and bounded parameters. They read back store/domain evidence before verified receipts. Other requests POST only to named Hermes profile `/p/van/v1/runs`; the gateway does not invoke models (`hermes/bridge.py:40`).
8. Hermes uses fixed `van_owner_runtime` MCP tools; no generic HTTP tool or canonical-memory promotion tool is exposed there (`hermes/mcp/owner_runtime_stdio.mjs:54`). Context candidates are forced INFERRED/MODEL_DERIVED by the runtime API. Browser/automation and Google/knowledge adapters require sealed action authority; their specialist work binds to Mission Activities.
9. `mission_result(hermes_run_id, outcome)` durably queues early reports and resolves the immutable gateway-observed run binding; historical start events are retained for legacy migration. Worker COMPLETED only enters VERIFYING; a separately selected mission verifier must observe declared postconditions/evidence for VERIFIED_SUCCESS. Empty/unobservable contracts yield UNVERIFIABLE, and conflicting terminal callbacks refuse. Callback replay/verification is state-guarded, leased and restart-safe (`mission/hermes_results.py`, `mission/service.py`).
10. Command status, mission/activity/evidence, needs-you, briefing, SSE/session events and observability retain correlation. Missing callback deadlines eventually report EXPIRED/never-heard-back; this is reporting, not a claim that remote execution failed. Gateway/Kotlin share owner status mappings including explicit outcome_unknown → UNKNOWN.

## Material remaining limits

- **Remote cancel is not implemented in this bridge.** HermesBridge has health/create/capabilities, no cancel/get-run/reconcile operation. Cancellation prevents new gateway-authorized starts; it cannot stop an already-running external operation, reverse a sent provider effect, or prove a remote process stopped. This must be explicit in UI acceptance.
- **Ambiguous dispatch reconciliation is a remaining integration requirement.** The fixed behavior preserves UNKNOWN and refuses redelivery; it does not invent a Hermes lookup/idempotent-create schema. A supported Hermes lookup by original command ID/run receipt and durable bind is needed to resume automatically. No live evidence for such a contract was available.
- **Live callback transport remains unqualified.** The local callback-before-binding race is corrected and tested. A handoff without any observed create receipt cannot be bound by guessing a caller-selected mission; supported remote correlation/lookup is still required to resolve that case. No real Hermes scheduling/transport evidence for the new inbox was collected.
- **Observer-bound assumption resolution and decision orchestration remain integration limits.** MCP can now record assumptions, inspect blockers and record premise assessments. Clearing an assumption requires a deterministic observer correlated with its postcondition; arbitrary model evidence strings cannot do it and no generic resolution tool is exposed. `/v1/decisions/escalate` remains owner-authenticated, outside the internal-token shim; model proposal wiring would need its own governed runtime wrapper. No current live demonstration of these planning ledgers was collected.
- **Some verification classes intentionally cannot qualify.** `verification/production.py:178` lists declared-but-unobservable strategies; RECEIPT has no independent provider receipt store and DOMAIN_ATTESTATION has no wired authority (`verification/production.py:298`). Arbitrary free-form missions and these contracts legitimately finish UNVERIFIABLE. Configuration and unit receipts must not be presented as LIVE proof.
- **Cached truth is a cache, not an independent current checkout observation.** ProjectRouter rejects missing/stale-marked rows but trusts supplied cached SHA/JSON. The mutation boundary depends on trusted cache ingestion and stale invalidation. No live repo-head reconciliation was performed.
- **Multi-device policy needs explicit UI acceptance.** Command status is scoped to the audited device row; mission list/detail/cancel uses shared owner-authenticated projections. The code does not enforce per-device mission ownership. This may be intentional for one owner with several devices, but must not be described as per-device isolation.
