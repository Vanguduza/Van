## 2. Operating architecture, authority and worker control

**Keep a single owner of each business/economic fact.** The native venue/financial owner retains raw orders, fills, correction, balances and finality; risk authority owns reservations/mandates; gateway owns authenticated commands/current projections and original-readback; existing outbox/ledger owns durable effect state; Research owns datasets/models/causal evidence; Android is a consumer, not a second financial engine. Hermes/Muse and browser/JEV are permissioned execution/proposal services, never substitutes for VAN authority. A live provider effect cannot be inferred from a PAPER fixture, a JSON boolean, a status badge, or an LLM response.

**Owner routes.** Use qualified Global DIAL MCP direct estate execution and typed original receipts when it is available; do not make Hermes a prerequisite for owner administration, and do not use the prohibited local `DESKTOP-S0CDKSD`. Do not require live trading to test source; native/demo and sandbox providers must be scoped to that environment. A scheduled/cross-repo Zuul experiment uses genuine Zuul and Depends-On; original GitHub PR CI remains the publication checker where currently specified. Do not substitute Github Actions for a chosen Zuul workflow. Admin/root permission never becomes financial permission.

**Single writer and bounded parallelism.** One integration writer owns the active branch, shared database migrations, canonical contract and release bundle. Normally at most two coding/model workers: one implementer and one source integration/reviewer, on disjoint worktrees; scale toward seven only if actual dependencies/resources/authorization permit. One frozen primary candidate and at most one successor ready for integration. Every task record names original unit+requirements+action IDs, allowed files, current source pins, owner, leases, tests, failure receipts, submission contract and exact next action. A worker's expiry, tool failure or model credit limit is a handoff, not permission to discard/reset work or claim it finished.

**Resource hygiene.** The Oracle Admin VM is memory constrained; send large public/Android/model suites to provisioned healthy workers. Pin backend/media ML-specific environments separately where needed. Before lengthy tests measure free bytes/inodes/process ownership, apply bounded timeouts and use uniquely owned `/tmp` directories. Preserve original raw artifacts and verify the owned processes have stopped before removing **only** their terminal-run scratch space; preserve Docker named volumes, Git source, mounted secrets, databases and active tasks. No destructive broad cleanup.

**Proof layers are distinct:** `DISCOVERED`, `SOURCE_IMPLEMENTED`, `FOCUSED_TESTED`, `REAL_SQL_HTTP_TESTED`, `HOSTED_CI_QUALIFIED`, `NATIVE_PROVIDER_QUALIFIED`, `INTEGRATED_CONSUMER_VERIFIED`, `INDEPENDENTLY_ACCEPTED`, `DEVICE_ACCEPTED`, `RELEASE_AUTHORISED`. These are evidence classifications, **not a new authority API**. A dimension may be `VERIFIED`, `UNVERIFIED`, `BLOCKED`, `FAILED`, `INCOMPLETE`, or `NOT_APPLICABLE_APPROVED`; no blanket percentage or automatic promotion.

## 5. Deterministic command, economic and data handling

### 5.1 Owner command to durable effect (all effectful operations)

```text
authenticated owner intent + exact original command ID / digest
  -> canonical envelope/schema and client-version check
  -> actual current device, actor, grant, purpose, account/cohort/environment and issuer
  -> scope/current clock/mandate/revision/lease and legal policy checks
  -> acquire canonical database/resource lock; compare original receipt/fingerprint
  -> current account/risk/funding/natively observed facts and available_at provenance
  -> reserve shared funds/risk or reject without effects
  -> persist PENDING original intent, immutable command receipt and outbox atomically
  -> recheck signer/current permission, source freshness, expiry and dispatch fence
  -> uniquely prepare/send provider command (only where native authority is qualified)
  -> observe original provider ID / unique fill / effect via native readback
  -> record APPLIED, REFUSED or UNKNOWN original effect; propagate exact economics
  -> reconcile and release/retain reserves once, commit event/receipt/review revision
  -> expose authenticated original-result GET; consumer renders exactly that outcome
```

Do not assert the precise serialization order of any inherited code before reading its actual transactional contracts. Preserve canonical locks and issuer requirements. In an API that does not yet have a durable side-effect command, keep the operation as a typed unapproved DRAFT/REFUSED rather than faking step completion. Provider/network calls should not occur inside an unbounded SQL lock; use the existing frozen dispatch/outbox protocol, explicit lease/fence and readback.

**Canonical outcome vocabulary for the plan** (not invented API response codes): `APPLIED_VERIFIED`, `REFUSED_NO_EFFECT`, `PENDING_ACCEPTED`, `UNKNOWN_RECONCILIATION_REQUIRED`, `CONFLICT`, `FAILED_BEFORE_EFFECT`, `RECONCILED_APPLIED`, `RECONCILED_NO_EFFECT`, and `DEFERRED_UNQUALIFIED`. Preserve existing published DTO status names and map these conceptual outcomes via reviewed typed contracts. A process exit `0`, HTTP 202, log line or model summary is not itself effect confirmation. Refusals may have a sanitised separate denial audit but must not have a business debit/order/version mutation.

### 5.2 Monetary/risk semantics

Use signed exact money and native precision/quantum with explicit venue, account, contract, currency, knowledge time, FX vintage and original native identity. **`NULL/UNKNOWN ≠ 0`** for fees, balance, margin, stop, collateral, volume, finality or possible fills. Preserve the original cash/position and adjustment ledger, replay order and source corrections; do not overwrite historical observations. For multi-leg family closes, calculate each original leg's permitted close quantity via exact rational proportional-floor or a distinct signed explicit-leg target, enforce original total/balance/lot and venue constraints, preserve all incomplete unknowns, and permit protective exits for independently confirmed siblings without resending an ambiguous close. Timing, slippage, fee correction, carry, unsettled effects and manual orders belong to risk/TCA. Do not extrapolate real profitability from a model fixture or paper backtest.

### 5.3 Causal data and model semantics

Every source observation records native source/event/received/ingest/available and correction times (where meaningful), original row/revision/sequence and permissions. Features and training labels must be reproducible as known at decision time. Leaked future news or revised prices cannot alter earlier decisions; reports preserve both historical knowledge vintage and later corrected truth. A model release pins exact input vintages, features, weights, allowed scope, calibration, baseline, test window, inference cache freshness and rollback plan. Neural models are challengers until independently evaluated. Kalshi remains read-only research first. The risk governor has final authority over every trading action, even when model confidence is high.

### 5.4 Gateway, assistant and Android semantics

Hermes/Muse/JEV/Commander may compute, propose and execute only through current scoped routes; durable original commands live with VAN owners, not with an unreviewed agent. Browser observations carrying owner-private content do not enter external model prompts; JEV proposals cannot bypass the final VAN-side authority/target check. Voice continuity follows device `last_spoken_segment`; device silence is not a server success. Android must use provisioned target host/identity, survive restart via non-secret original request and result, and keep floating-assistant artifacts unadmitted until original Candidate B review. Final physical S24 tests are the final M8 stage, not a prerequisite to isolated source tests.
