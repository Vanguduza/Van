# Glimmer local qualification machinery

`trading/vati/cognition/glimmer_qualification.py` hashes actual local artifact bytes, probes actual Linux RAM/architecture/CPU/host identity, runs 20–100 bounded calls against an already-installed model, validates exact model/artifact response identity and a typed abstention contract, measures each latency and sampled model RSS, seals the measured benchmark, and evaluates independent artifact/license/Placement Governor/hardware/sandbox/data-class/reliability/latency/memory gates.

The executable operator entrypoint is `tools/cognitive/qualify_glimmer.py`. It accepts a pre-existing pinned artifact and license, placement and sandbox evidence files. It either consumes an existing sealed benchmark or measures an already-running explicit literal loopback HTTP endpoint plus supplied process PID. Proxy dispatch and redirects are disabled. Response size, sample count and deadlines are bounded. It never downloads weights, starts a model daemon, spends Meta fees, writes provider credentials or activates Glimmer.

A clean local result is `LOCAL_CHECKS_PASSED_GOVERNED_ADMISSION_PENDING`, with `live_qualified=false` and `activation_performed=false`. It cannot be used as a self-approved Placement Governor or provider-activation receipt. The accepted provider configuration still requires the normal owner/governed qualification path, and remains empty by default.

Required external inputs are the actual immutable model artifact and reviewed license; exact approved host/artifact Placement Governor receipt with expiry, reserved RAM and T2 deadline; host/artifact-bound sandbox evidence covering non-root operation, credential/tool isolation, retention/logging and admitted data classes; and authentic local inference/benchmark evidence. `oracle-admin` is excluded. Protected control/trading/coordinator hosts require an explicit owner capacity exception reference in the owning governed receipt. Hardware probe and placement host must agree. Higher-private data classes require explicitly qualified sandbox admission.

Tests use clearly labeled fixture artifacts and a real temporary loopback HTTP server, not real Glimmer weights. They prove hashing, transport, measurement, response identity and gate enforcement. They do not qualify an actual model or estate host. `glimmer-host-probe.json` records this Codex environment's measured hardware only; it is not a DIAL Placement Governor admission.
